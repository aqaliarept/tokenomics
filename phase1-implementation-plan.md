# Phase 1 Implementation Plan — Python PettingZoo AEC Environment

Port the Go domain (`emulation/domain/`) to pure Python, expose as a PettingZoo AEC environment for MARL training. Per ADR-0001 and ADR-0002.

The env, port, and a MAPPO smoke loop are built (ADR-0001–0006): observable per-iter eval curves, centralized critic, vectorized rollout, difficulty curriculum.

> **Superseded by the ADR-0025 supply-chain redesign (2026-06).** Track A below proved the *old* flat model (single-capacity producers, capacity-only products, recipe-splitting ordering agents) poses a learning problem. The domain is being rewritten around whole-product orders, multi-capacity producers, composite assembly, and inventory pipelining. **The Track A target numbers no longer apply** — baselines and targets must be re-derived against the new model. Track A results are kept below as the historical record of the old model. See **Track B** for the redesign rollout.

**Status (old model): bar cleared.** The trained policy survived the full horizon and beat the strongest baseline on the canonical seeds.

**Old target (no longer valid): beat `restore_when_low` + `even_split` — return ≈ 3230, ≈ 359 consumer completions, 0 % death over horizon 100.**

## Track A — DONE (beat the baseline bar)

The original collapse (`dead 1.00`) was **not** an instability/tuning problem — it was a stack of trainer correctness defects. Diagnosed and fixed across `docs/track-a-findings.md` sessions 3–4:

| Defect | Fix |
|--------|-----|
| GAE walked buffer adjacency, not the real `(env,agent)` trajectory | ADR-0017 explicit successor links |
| PPO rollout cuts reset live episodes | ADR-0018 persistent rollout episodes |
| ValueNorm changed V(s) at fixed weights | ADR-0019 output-preserving PopArt |
| Producing policy stayed near-random | ADR-0020 temperature |
| Action aliases corrupted producing credit | ADR-0021 producing action mask |
| Critic omitted the acting decision context | ADR-0023 agent-conditioned critic |
| Trust region too permissive | ADR-0024 target-KL `0.008` |

The original Track A levers (A1 critic fix, A2 long-run + LR schedule, A3 eval-gated curriculum, A4 reward-shaping) were explored along the way. **The winning config uses no curriculum and no shaping** — A3/A4 were tried and ruled out, not needed (ADR-0009/0010/0016/0022 record the negative results). The real wins were the correctness fixes above.

## Open items (not Phase-1 blockers)

1. **Monotonic training stability — unresolved.** Convergence is non-monotonic: e.g. seed 5 evaluates dead iters 30–60, recovers ~70. best-on-eval ships the survivor and protects deployment, but the training curve still shows the dip. **No established mechanism** — loss-of-plasticity / feature-rank collapse is unmeasured speculation (no rank measurements, no PFO experiment). Open research.
2. **Full-seed robustness — unproven.** Only seeds 1 / 2 / 5 validated under the final config. Bad-init seeds (0,3,4,6,7,8,9) were never re-swept post-ADR-0018. The win is "survives on canonical seeds," not "survives on all seeds."

**Post-Phase-1 (separate arc):** the deep-research 6-phase roadmap — RL-per-decision-block, graph/history critic, investment & durability, planner/regulator. Not Track A.

## Track B — supply-chain redesign (ADR-0025)

Rewrite the domain around whole-product orders, multi-capacity producers, composite assembly, and inventory pipelining. Sequence bottom-up so each layer is testable before the next depends on it. `domain/` stays pure; all reward/space logic stays in `env/`.

**B1 — Domain: products & recipes. DONE.** Extended the process sheet with `inputs: dict[Product,int]` + `is_primal`/`is_composite`; `Configuration.inputs_of` and cycle-safe `recipe_inputs_closure`; `validate()` rejects inputs with no sheet or non-positive quantity; loader parses optional `"inputs"`. Composite 2-level fixture at `tests/fixtures/composite.json` (30→{20,11}, 20→{10}); `phase1.json` stays primal-only until B7. Tests: `tests/test_domain_recipes.py` (5). *Done: domain encodes a primal+composite product set and the recipe graph is queryable.*

**B2 — Domain: multi-capacity producers + bundle auction. DONE (auction core).** `ProducingAgent` owns `capacities: dict[type,cap]`; `Bid` carries a bundle `capacities` map; `produce()` runs the atomic price-greedy auction (clear only if every required type fits this cycle), scalar cut-off = lowest accepted price, per-type degradation. Carry-over (`in_progress`) removed. Config: multi-type producers (`ProducingAgentConfig.capacities`; legacy single-`type` form still loads); `Restoration`/`Upgrade` gain a target `type`. Tests: `tests/test_domain_auction.py` (5). *Note:* `system.py`/`ordering_agent.py`/`env` reference old single-type shapes → runtime-red until B4/B5 rewire (per plan sequencing). *Done: atomic multi-type acceptance, over-large single-cycle rejection, per-type degradation.*

**B3 — Domain: inventory + composite assembly (capacity reserved at acceptance). DONE.** `ProducingAgent` gained input-product `inventory`, `inventory_limit`, and `reservations`; `Bid` carries `product`+`inputs`; `produce()` re-validates carried reservations against post-degradation capacity (atomic re-run, cheapest-first drop, disjoint spared), assembles those whose inputs arrived, ages waiters to `RESERVATION_TTL`(=2) then fails, and reserves new composites missing inputs. Tests: `tests/test_domain_assembly.py` (5) — same-cycle assembly, blocking, TTL fail, no-overcommit, degradation cheapest-first/disjoint-spared. *Done: composite completes same-cycle when pre-stocked; waiter holds+blocks+fails on TTL; degradation drops only the reservation needing the deficient type.*

**B4 — Domain: investment (inventory expansion) + system death + per-producer fund. DONE (fund + death + expansion).** Added `InvestmentType.INVENTORY_EXPANSION`, `InventoryExpansion(require,increases)` config, `ProducingAgentCommand.do_inventory_expansion`; `handle_cmd` emits the request, `investment_completed` raises `inventory_limit`. Rewrote `distribute_investment_fund` **two-stage**: stage-1 per-producer budget proportional to scalar cut-off price (NaN producers split remainder equally → order count can't raise a producer's share); stage-2 splits the producer's whole budget across its orders sorted by fixed priority **restoration(0) → replenishment/non-investment(1) → upgrade(2) → inventory expansion(3)** via `_order_priority`/`_INVEST_PRIORITY`. New `is_dead()`: a capacity type at zero across all its owners → terminate. Tests: `tests/test_domain_investment.py` (4). *Stage-2 refined in B5 (ADR-0027): greedy survival-first to per-order cost targets, lower priorities expire — no longer equal-split.* *Done: fund is producer-first; episode ends on the new death condition; inventory limit grows on completed expansion.*

**B4.5 — Domain: whole-product order integration. DONE.** Bridges B2–B4 into a runnable domain. Rewrote `Order` to the whole-product model: tracks `product`, `quantity`, per-unit `unit_capacity`/`unit_inputs`, and aggregates outcomes by sub-order quantity (`sub_completed`/`sub_rejected`/`sub_processing`) — completed only when `completed_qty == quantity`, else rejected on all-rejected or TTL; funding API (`fund`/`requires_funding`/`cut_off_price`) preserved for `distribute_investment_fund`. `ConsumerRequest` gained `quantity` (default 1); `Bid` gained `quantity`. Rewrote `OrderingAgent` to split an order's **quantity** over **eligible** producers (owns every required capacity type) into one whole-bundle bid per producer — capacity + inputs scale with sub-quantity; guards: eligibility, Σquantity = order quantity, Σtokens = order tokens, no zero-quantity sub-order (the largest-remainder apportionment itself lives in B5 env decode). Rewired `System.complete_cycle` to the sub-order API and dropped the obsolete `in_progress` dangling-bid cleanup. Deleted obsolete `tests/test_domain_parity.py` (Go single-type parity premise is dead). Tests: `tests/test_domain_orders.py`, `test_domain_investment.py`, `test_domain_assembly.py`. *Done: domain runs full cycles end-to-end on the new model (34 domain tests green); `env/`/`eval/`/`simplex`/`train/` remain red-by-design pending B5–B8.* *Note:* `phase1.json` is incompatible with the new eligibility rule (every product needs 2 types, each producer owns 1) → exercised configs are built inline / `composite.json` until B7 re-derives `phase1.json`.

**B4.5 review fixes (multi-cycle correctness). DONE.** Closed 7 review findings on the integration: **(1)** `Order.info()` now exposes only the *unresolved* quantity (`quantity − accepted_qty`) and *available* tokens (`tokens − burnt_tokens`); `OrderingAgent.place_order` skips zero-unresolved orders — partially-completed/reserved orders are no longer re-dispatched every cycle. **(2)** Sub-order tokens are **burnt at auction acceptance** (`sub_accepted`), so a later-failed reservation is not refunded; `produce()`/`ProductionResult` now report four disjoint outcomes — `accepted` (cleared this cycle, tokens burnt), `completed` (delivered), `failed` (a prior reservation dropped/TTL'd), `rejected` (never cleared) — and the order derives close/reject from `accepted/completed/failed`. **(3)** `System.complete_cycle` drops orphaned reservations whose parent order closed (was crashing `must_get` next cycle). **(4)** `investment_rejected` handles `INVENTORY_EXPANSION` (was raising `unsupported` → sim termination). **(5)** concurrent inventory-expansion gated via `inventory_expansion_running`. **(6)** loader parses `inventoryExpansion`. **(7)** a reservation TTL-failing in `produce()` returns its capacity to the same-cycle budget so a now-fitting bid is accepted. *Done: multi-cycle composite + investment flows are correct; 34 domain tests green.*

**B5.0 — Domain: replenishment order path + greedy funding (ADR-0027). DONE.** B5's "replenish dims emit orders" needs a domain path that did not exist (only a reserved priority slot). Added `ReplenishmentRequest` (its own kind, not investment), `Order.new_replenishment_order` + `ReplenishmentRequestCompleted/Rejected` events, `ProducingAgentCommand.replenishments: dict[Product,int]`; `handle_cmd` emits one request per positive-qty input and tracks `outstanding_inbound` for the env's joint headroom `H = inventory_limit − held − inbound`; completion deposits into the requester's inventory, rejection clears inbound. Rewrote stage-2 fund allocation to **greedy survival-first to per-order cost targets** (ADR-0027): config `cost` per investment + `replenishCostPerUnit`; unfunded low-priority orders **expire** (skipped in `start_ordering`, rejected via `Order.expire()` in `complete_cycle`). Tests: `tests/test_domain_replenishment.py` (14). Closed a 3-finding review (view fields populated, validate-before-mutate, real greedy not even-split). *Done: producers buy inputs into inventory; fund is greedy survival-first; 49 domain tests green.*

**B5 — Env: spaces + encode/decode. DONE.** `EnvSpec`/`build_spec` rebuilt for the multi-capacity model: `capacity_types` = union over producers (no more one-producer-per-type), global input-product vocabulary `G` (sorted union over composite recipes), per-producer `producer_inputs` (inputs of composites it is eligible to assemble), `max_replenish` (config, default inventory_limit). Ordering action `Box(K×P)` → `decode_ordering` restricts each order to its **eligible** producers, apportions **quantity first** via largest-remainder, then **tokens following the realized integer quantities**, drops zero-quantity sub-orders → `list[SubOrder]`. Producing action `Box(G+3)` → `decode_producing` does **joint replenishment over shared headroom** `H` (use-as-is when `Σ d_g ≤ H`, else scale to exactly `H` by largest-remainder; `raw ≤ 0 → 0`; irrelevant dims no-op) + toggles `restoration/upgrade/inventory_expansion` (decode owns all gating — already-running / unconfigured ignored, ADR-0026). Obs rebuilt: per-type capacity+max, invest-running flags, per-input stock, inventory units/limit/headroom, producer summary; critic global state resized to `5P+1`. `aec_env` rewired (both actions continuous, ordering decode uses the eligibility view). Tests: `test_simplex.py` (13: spec, decode_ordering conservation/eligibility/quantity-first, decode_producing replenish/headroom/gating), `test_env_api.py` (api_test, seed_test, random rollout, obs-in-space, global-state shape). *Done: api_test + conservation + headroom-scaling + irrelevant-dim-noop all green.*

**B6 — Env: reward. DONE.** Reward factored into `cycle_reward(result, held)`: `+10` consumer / `+1` instrumental (investment + replenishment) / `−1` in-progress / `−5` rejected, minus a flat `R_HOLDING_PER_UNIT = 0.1` per inventory unit held into the next cycle (env-layer training cost, ADR-0025). Tests in `test_env_api.py`: penalty is linear in units held and independent of completions. *Done: holding penalty scales with units held.*

**B7 — Eval: re-derive baselines + targets. DONE.** `eval/baselines.py` rewritten for the continuous interface (policies emit raw `Box` vectors): producing baselines build `G+3` vectors (toggle gating via raw>0), ordering baselines build `K×P` logit vectors; added **`stock_aware`** (restore-when-low + top input stock up to a target — the only producing baseline that feeds composite assembly). `phase1.json` re-derived as a balanced composite supply chain (`10→` cap-1, `11→` cap-2, `20→{10}` cap-3, `30→{20,11}` cap-4; one consumer wants `30`); recipe capacities + restoration/replenishment costs tuned so every producer's cut-off price ≈ 20, so the per-producer (cut-off-proportional) fund stage-1 splits evenly instead of the top producer hogging it. `test_signal_exists` now compares `noop` vs `stock_aware`. *Done: signal table below; the strongest baseline clearly beats do-nothing.*

**B5–B7 review fixes. DONE.** Closed 3 findings on the env/eval layer: **(1)** `Configuration.validate()` now rejects a product whose required capacity bundle is split across producers (no single producer owns it all) — such a config has no *eligible* producer and used to pass validation then crash `decode_ordering` on an empty eligible set (ADR-0025 eligibility). **(2)** order-slot count `K` is now **config-derived** (`max(ORDER_LIFETIME, INVESTMENT_STREAMS + ORDER_LIFETIME × max_relevant_inputs)`) instead of a hardcoded 3: a producer's ordering agent can hold 3 gated investment orders plus one replenishment stream per relevant input (each stacking up to the order TTL), so the old K=3 silently dropped orders into an unobservable, uncontrollable even-split fallback (reproduced 5 funded orders on `phase1.json`). **(3)** `ordering_proportional` now weights eligible producers by **bundle throughput** `min_t(capacity[t] // unit[t])`, not total capacity (irrelevant-type capacity no longer inflates a producer's share), and clamps logits to the action bound. **(4)** `validate()` rejects duplicate consumer ids and consumer/producer id collisions (they share the ordering-agent / env-agent namespace → would double-step one agent). **(5)** `ordering_proportional` throughput now nets out live reservations (`ProducingAgent.reserved_capacity()`) so a fully-reserved producer is not over-weighted. *Done: 94 tests green (only B8 trainer red-by-design).*

**Eligibility redesign: authoritative `produces` (ADR-0028). DONE.** Eligibility flipped from *derived* (a producer owns every capacity type the recipe requires) to *declared*: `ProducingAgentConfig.produces: frozenset[Product]` is the single source of truth read by `OrderingAgent` and `env/spaces.build_spec`. `validate()` now (a) rejects a producer that lists a product whose required capacity types it does not own, and (b) rejects any process-sheet product produced by no one (replaces the old split-bundle check while keeping its empty-eligible-set guarantee). `phase1.json`/`composite.json` and all inline test configs gained `produces` lists and dropped the legacy `"type"/"capacity"` shorthand for the `capacities` map. Behavior-preserving for the Phase 1 economy (each product had one capacity-eligible producer): `signal_check` unchanged (`stock_aware`+`even_split` = 100 cycles, 0% death, 100/100 consumer, return 1267). *Done: 97 tests green (only B8 trainer red-by-design).*

**Capacity-free ordering: producer owns recipe expansion (ADR-0029). DONE.** Removed the last capacity leak onto the ordering side. `OrderInfo`/`Order` dropped `unit_capacity`/`unit_inputs`; `OrderingAgent.handle_cmd` now routes a capacity-free `SubOrder(order_id, product, quantity, tokens)` instead of building `Bid`s. `ProducingAgent` is constructed with the process sheets for the products it `produces` and gains `place_sub_orders`, which expands each routed sub-order into an internal `Bid` (bundle + inputs scaled by quantity) from its own sheet — the existing atomic auction (`Bid`/`place_bids`) is untouched, so auction/assembly unit tests still drive hand-crafted bundles directly. RL **ordering obs** stripped of capacity: slot = `(active, tokens, quantity)`, producer summary = cut-off price only → `ordering_obs_dim = k·3 + P + 1` (was `k·(3+T)+2P+1`); producing obs + critic state unchanged. White-box `ordering_proportional` reads the recipe from the process sheet now. Behavior-preserving: `signal_check` unchanged (return 1267). *Done: 98 tests green (only B8 trainer red-by-design).*

**Review fixes: death detection + baseline + cost validation (ADR-0030). DONE.** Three findings closed: **(1)** `ordering_proportional` no longer collapses throughput 0 and 1 to the same logit (`log(max(.,1))` → floor a 0-unit producer at `-BOUND` so a fully-reserved producer gets ~0 share, not half the order). **(2)** `validate()` rejects non-positive `restoration/upgrade/inventoryExpansion.cost`, `replenish_cost_per_unit`, `max_replenish` (zero cost funds nothing; non-positive ceiling corrupts replenishment apportionment). **(3)** `System.is_dead()` now judged **per declared product** — a product is dead when no producer that `produces` it still holds every required capacity type, so a chain broken by exhausting the sole declarer of a product terminates immediately instead of running to horizon (the old type-level check treated capacity as interchangeable across owners). Behavior-preserving: `signal_check` unchanged (return 1267). *Done: 103 tests green (only B8 trainer red-by-design).*
