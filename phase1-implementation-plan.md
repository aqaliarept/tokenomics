The env, port, and a MAPPO smoke loop are built (ADR-0001–0006): observable per-iter eval curves, centralized critic, vectorized rollout, difficulty curriculum.

Track A results are kept below as the historical record of the old model. See **Track B** for the redesign rollout.

## Track A — DONE (beat the baseline bar)

The original collapse (`dead 1.00`) was **not** an instability/tuning problem — it was a stack of trainer correctness defects. Diagnosed and fixed across `docs/track-a-findings.md` sessions 3–4:

| Defect | Fix |
|--------|-----|
| GAE walked buffer adjacency, not the real `(env,agent)` trajectory | ADR-0017 explicit successor links |
| PPO rollout cuts reset live episodes | ADR-0018 persistent rollout episodes |
| ValueNorm changed V(s) at fixed weights | ADR-0019 output-preserving PopArt |
| Producing policy stayed near-random | ADR-0020 temperature |
| Action aliases corrupted producing credit | ADR-0021 producing action mask |
| Critic omitted the acting decision context | ADR-0023 agent-conditioned critic |
| Trust region too permissive | ADR-0024 target-KL `0.008` |

The original Track A levers (A1 critic fix, A2 long-run + LR schedule, A3 eval-gated curriculum, A4 reward-shaping) were explored along the way. **The winning config uses no curriculum and no shaping** — A3/A4 were tried and ruled out, not needed (ADR-0009/0010/0016/0022 record the negative results). The real wins were the correctness fixes above.

## Open items (not Phase-1 blockers)

1. **Monotonic training stability — unresolved.** Convergence is non-monotonic: e.g. seed 5 evaluates dead iters 30–60, recovers ~70. best-on-eval ships the survivor and protects deployment, but the training curve still shows the dip. **No established mechanism** — loss-of-plasticity / feature-rank collapse is unmeasured speculation (no rank measurements, no PFO experiment). Open research.
2. **Full-seed robustness — unproven.** Only seeds 1 / 2 / 5 validated under the final config. Bad-init seeds (0,3,4,6,7,8,9) were never re-swept post-ADR-0018. The win is "survives on canonical seeds," not "survives on all seeds."

**B8 trainer review fixes — BAR CLEARED (2026-06-15).** A 3-finding trainer-layer review pinpointed the wall as a *trainer* defect (not the env incentives above): **P1a** the producing actor's replenishment quantity dims round to zero unless raw > ~0.5, but `prod_log_std=-2` (σ=0.135) at a ~0 mean samples that ~0.01% of the time → the replenishment→assembly path is never explored, no consumer-reward gradient. Fix: per-dim producing log_std (replenishment dims σ=1.0, `--prod-replen-log-std`) + a positive output-bias init on those dims (`--prod-replen-bias`, default 2.0) so greedy eval fires replenishment from iter 0. **P1b** `actor_update` summed log-prob/entropy/KL over every action dim, but `decode_producing` no-ops most input dims (inputs a producer doesn't assemble) and unavailable/running toggles → gradient noise + wasted target-KL budget. Fix: per-transition active-dim mask (`producing_action_mask`) stored in `Buf`, applied to log-prob (masked sum), entropy (mean over active dims), and KL. **P2** `capacity_health` (shaping signal) was a mean over total capacity that stays ~0.75 when one of four producers dies, so `low_cap_thresh=0.3` never fires near the per-product death cliff (ADR-0030). Fix: bottleneck health = worst product's best-declarer's weakest required-type ratio → 0 exactly when a declarer loses a required type. Tests: `test_train_smoke.py` Buf fixtures carry the mask — 111 green.

**B8 trainer review-2 fixes (masking + logging + coverage) — BAR HELD (2026-06-15).** A second trainer-layer review (`REVIEW.me`) raised five findings; the four contained ones landed, the two action-space reparameterizations are deferred below. **F1 (ordering behaviorless)** — every product in canonical `phase1.json` has a single declarer, so the ordering softmax over one producer is always 1: the ordering actor consumed gradient + target-KL budget with zero env effect. Fix: `ordering_action_mask` zeros the log-prob/entropy/KL contribution of (a) any slot whose order has ≤1 eligible producer and (b) the non-eligible producer dims of a multi-eligible slot. **F3 (zero-headroom replenishment)** — `producing_action_mask` now drops replenishment dims when `view.headroom ≤ 0` or `max_replenish ≤ 0` (decode emits nothing there anyway). **F4 (entropy logging)** — the logged producer entropy now uses the same per-transition active mask as `actor_update`, so inert wide-σ replenishment dims no longer inflate the diagnostic. **F5 (coverage)** — +6 tests: bottleneck `capacity_health` (sole-declarer death + healthiest-declarer-wins), ordering mask (singleton inert / multi active), zero-headroom replenishment mask, per-dim log_std + mean-bias init, masked-update-leaves-inactive-dims; stale capacity-health docstring corrected. `signal_check` after retrain (seed 1): 100 cycles, 0% death, return **1325 > 1267** — no canonical regression (the ordering actor was already behaviorless; masking just stops it wasting the KL budget). 117 tests green.

**B8 review-3 fix (P2: Adam momentum drift on frozen dims) — BAR HELD (2026-06-15).** Follow-up review found masking log-prob/entropy/KL is necessary but not sufficient: a per-dim head active in one batch leaves Adam momentum `(m, v)` behind, so when the next batch masks that dim in every row its gradient is zero yet `opt.step()` still applies the stored momentum — the inactive head and its `log_std` drift. Fix in `actor_update`: for dims globally frozen across the batch (`mask.sum(0) ≤ 0`), snapshot the GaussianActor per-dim output params (final-layer weight row + bias, `log_std`) before `opt.step()` and restore them after, pinning frozen heads regardless of momentum (shared trunk is not per-dim, so only the authored per-dim heads are pinned). +1 test (`test_masked_update_resists_adam_momentum_on_frozen_dim`: warms the optimizer with the dim active, then masks it and asserts no drift) — the prior masked-update test used a fresh optimizer and missed this. `signal_check` after retrain (seed 1): 100 cycles, 0% death, return **1325 > 1267**, best eval 1325.1 (bit-identical to pre-pin). 118 tests green.

**B8 review-4 fix (P2: Adam state + shared-trunk drift) — BAR HELD (2026-06-15).** The round-3 final-layer restore pinned param *values* but Adam state still advanced, and — the dominant defect — could not touch the **shared trunk**: when the *entire* batch mask is zero (the ordering actor in canonical config, where every order is singleton-eligible, so its mask is all-zero every iteration) the masked loss is constant in the params, the gradient is zero everywhere, yet `opt.step()` still pushes the trunk on stored momentum — a behaviorless actor drifting (measured ~0.015 trunk move, ~0.77 output move per update). Fix in `actor_update`: **(a)** skip the update entirely (`return 0.0`, no param/optimizer-state change) when `mask.sum() == 0`; **(b)** for partially-frozen batches, additionally snapshot+restore the frozen dims' Adam moment slices (`exp_avg`, `exp_avg_sq`, `max_exp_avg_sq`) alongside the param slices, so an inactive dim's optimizer state does not decay. +1 test (`test_all_zero_mask_skips_update_entirely`: warms the optimizer, then an all-zero batch must leave trunk, output, and Adam step counter untouched) and the existing momentum test now also asserts the frozen dim's `exp_avg`/`exp_avg_sq` are unchanged. `signal_check` after retrain (seed 1): 100 cycles, 0% death, return **1325 > 1267**, best eval 1325.1. 119 tests green.

**Deferred further improvements (action-space redesigns — generality, not canonical-result bugs).** Both are the review's own "Further Improvements"; each needs a new ADR, a `CHECKPOINT_VERSION` bump, and a retrain. Neither changes the canonical bar (masking fully covers the canonical config), so they are scoped out of the bar-clearing work and tracked here:
1. **Ordering contrast-logit reparameterization (review F1).** The ordering action is a full Gaussian over `P` per-producer logits per slot, but softmax has a translation null direction (only logit *differences* matter), so even a multi-eligible slot carries one behaviorless degree of freedom that still spends likelihood/KL. Replace the `P`-logit slot with `n−1` contrast logits over the slot's eligible producers (drop the null direction; mask irrelevant producers). Only bites when a product has ≥2 eligible producers — none in canonical `phase1.json` — so it pairs naturally with **B9** producer-competition, where routing first becomes behavioral.
2. **Replenishment quantity head (review F2).** `decode_producing` scales each raw replenishment real by the producer's `max_replenish`, so the fixed raw mean-bias (default 2.0, ≈20 % of the ceiling) is calibrated only for the canonical `maxReplenish = 10`; at `maxReplenish = 1` the greedy action rounds back to zero and nonzero exploration becomes rare again — the original wall returns for any leaner config. A single shared rounded-Gaussian cannot hold a sensible nonzero quantity across very different ceilings. Replace it with a configuration-normalized nonnegative quantity distribution or a zero-inflated categorical quantity head per input. Required before the trainer can serve as a general (multi-config) hyperparameter testbed; the canonical `maxReplenish = 10` result is unaffected.

### Proposed B9 — Seeded domain randomization and meaningful routing

The canonical `phase1.json` remains the deterministic regression benchmark; do not replace it. Add a separate randomized training/evaluation scenario family to test generalization and make the ordering policy behaviorally meaningful.

**Consumer demand randomization.** At `env.reset(seed=...)`, derive the complete episode demand schedule from the environment RNG. Randomize product selection, quantity, budget, and optionally arrival timing within bounded distributions, then keep that schedule deterministic for the episode. Avoid unseeded per-cycle randomness. The same episode seed must reproduce identical demand so baselines and trained policies face exactly the same workload. Observations must expose the current order's product, quantity, and budget; otherwise demand randomization creates hidden-state partial observability rather than a useful control problem.

**Producer competition.** Configure two or more eligible producers for selected products, with controlled differences in capacity, degradation, price/cost, inventory, and restoration characteristics. The current canonical topology has one producer per product, so its ordering softmax has no behavioral choice. Duplicate eligibility creates real routing decisions: price versus remaining capacity, reservation contention, degradation risk, and load balancing. Retain at least one simple single-producer product so both singleton masking and competitive routing remain covered.

**Producer/configuration randomization.** At episode reset, optionally sample bounded numeric variants of initial/max capacity, degradation, restoration/upgrade cost and effect, inventory limit, replenishment ceiling/cost, and producer eligibility/recipe cost. Hold the sampled configuration fixed for the full episode. Start with approximately ±10–20% numeric variation and add topology variation only after numeric randomization is stable. Every generated economy must pass `Configuration.validate()` plus a feasibility check proving each product has at least one eligible producer and the composite supply chain can be completed under some admissible policy.

**Observability contract.** Every randomized parameter required for a decision must be present in local observations or intentionally represented through history/recurrent state. In particular, agents need sufficient information about product identity, eligibility, current/max capacity, degradation, replenishment limits/costs, inventory limits, and investment availability. Hidden randomized mechanics would test memory under partial observability, not policy robustness, and must be a separate experiment.

**Seed protocol.** Use disjoint deterministic seed sets: training seeds for rollouts, validation seeds for best-checkpoint selection, and held-out test seeds used only for final reporting. Never select `best-on-eval` using the held-out test set. Store the generator version and sampled episode parameters in run artifacts so a failed economy can be replayed exactly.

**Evaluation matrix.**

| suite | purpose | configuration |
|---|---|---|
| canonical | regression and baseline comparability | unchanged `phase1.json`, fixed demand |
| in-distribution validation | checkpoint selection and tuning | unseen seeds from the bounded training distribution |
| held-out numeric | interpolation/generalization | unseen seeds and parameter combinations within configured bounds |
| held-out topology | structural robustness | producer eligibility/competition patterns excluded from training |

Report mean, median, standard deviation, and worst-case return together with fulfillment rate, death rate, rejected orders, inventory holding cost, and routing concentration. Require multiple independent model-training seeds; one environment seed or one successful policy initialization is not evidence of robustness.
