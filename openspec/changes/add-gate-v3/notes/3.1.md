## What changed

### `/srv/research/tokenomics/tokenomics/tokenomics/eval/gate_cli.py`

- **Selection.** `run_screen(..., member_waves="v3")` (CLI `--member-waves v3`) dispatches to
  `run_screen_v3`.
  - A v3+ registry without `--member-waves v3` is refused, and so is `--member-waves v3` on a
    v1 / v2 registry.
  - The v3-only flags are refused on the one-wave path.
  - The one-wave path is unchanged otherwise.
- **Pilot roster refused outside `--dry-run`** (binding 1.1 carry-forward). The check is at the
  top of `run_screen`, so it covers both paths.
- **`plan_v3(scope, roster, rows)`** is pure and decides D3 waves 1–2 from the rows alone. A
  resume replays it.
  - **Wave 1** runs every member on the development gate worlds except `ws_wide`. While the
    rows are complete, the replacement plan names reserve sub-waves (on demand). Replacement is
    zero-baseline plus, for region families, **bar-death**: `bar_dead_worlds` finds a world
    whose per-episode argmax member (largest replicate-mean units, ties to the smallest id) died
    in any replicate. It feeds `registry.plan_replacements(..., bad=...)`, and a bar-dead reserve
    is skipped like a zero one. sparse_wide keeps its v2 rule.
  - **Headroom after wave 1** per family × size (sparse_wide 12 and 42, `ws_loaded` 12). A
    failure is **excluded**. If a size is left with no admitted family, the screen stops before
    wave 2 (exit 3). `ws_wide` still counts as possible at 42 until wave 2 decides it.
  - **W2** = the members that are the per-episode argmax on at least one *admitted* wave-1
    episode, plus every `entity_planner` member (`roster.wave2_members`).
  - **Wave 2** runs W2 on `ws_wide` plus its reserve sub-waves, then the headroom check for
    `ws_wide` / 42. A size with no admitted family stops (exit 3).
- **`screen_outcome_v3`** builds the outcome:
  - the screened registry: both waves' replacements, `bar_deaths` (world, episode, member), the
    headroom of every family × size, `record_exclusions`, which marks both splits, gate worlds
    and reserves, and `screened_on` = the draft's hash;
  - pruning by `never-argmax-two-wave-v1` (`roster.prune_two_wave`) over the admitted episodes
    of both waves;
  - **per-family X / Y**: 2.3's `calibrate_families` over the admitted final worlds' rows of the
    kept members, written as a v3 parameter file;
  - excluded worlds' rows enter no W2 winner set, no pruning evidence and no X / Y.
- **Reported, never gating:**
  - **attainability**: per world 1 / (mean argmax fill); per (size, regime) over admitted
    worlds and per (family, size, regime) over all final worlds, each against the regime's
    margin, flagged `unattainable` below it;
  - **routing**: per world `reach_gain_w` = (best of MWW / MS − best of the 9 blind routers) /
    best blind, all with `entity_planner`, against 0.05 and the world's floor. The floors follow
    D3: shocked, 3·sd(d)/√n; calm with a stochastic side, 3·√(Σ s²/n); calm deterministic, 0.
    `router_spread_w` is a column only. The family reads `routing_matters` iff the counting
    worlds are ≥ 1/3 of its admitted worlds; a family whose worlds all lack the routers reads
    `insufficient_members`;
  - **v2 against v3 X / Y per family**, and the **frozen v2 roster's bar beside the v3 bar** on
    the v2 worlds.
- **`run_screen_v3`**, the driver:
  - it loops plan → run the missing jobs (`_execute`) → plan until complete;
  - the pins add `member_waves`, `region_shocked_episodes`, `reuse_rows` (path and sha256),
    `shock_profile` and `worlds_per_family` (v3 path only, so v1 / v2 pins are unchanged);
  - a resume with equal pins replays the plan from the rows, and a row outside the plan is
    refused (`check_rows`);
  - it writes `screening.json` (both waves with members, gate worlds and reserve sub-waves; W2;
    not carried; headroom; exclusions; stop; replacements; bar deaths; pruned; families; the
    tables; `acceptance_read` and the "not an acceptance read" note on dry runs), plus
    `headroom.csv`, `attainability.csv` and `routing.csv`;
  - when every size keeps a family, it writes `frozen/{worlds,roster,side_effect_params}_v3.json`,
    all three with one `screened_on`. Dry runs name them `worlds-v3-dry-run`, `roster-v3-dry-run`
    and `side-effect-params-v3-dry-run`.
- **Reductions (D3).**
  - `--region-shocked-episodes N` cuts shocked region entries to their first N episode seeds in
    both splits, so the screened registry carries it.
  - `--reuse-rows <EXP-0047 dir>` (`_reuse_v2_rows`) refuses a source whose pins are not the v2
    draft. It runs the reproduction check: one world-episode per (size, regime), the first gate
    world by id and its first episode, for all v2-draft members and replicates, which must equal
    EXP-0047's rows field for field. Only then are the other v2-world rows of the v2-draft
    members appended from EXP-0047. A mismatch refuses the reuse. The result is recorded in
    `spec.json` "reuse".
- **New dry-run flags:** `--worlds-per-family N` and `--shock-profile shocks-i-smoke`
  (departures 3 and 4). Both are pinned.

## Departures from the task text / sources (each for the reviewer)

1. **`registry.py` is edited, although tasks.md names `gate_cli.py` and `roster.py`.**
   Bar-death replacement must go through the existing reserve-order rule. Generalizing
   `plan_replacements` with a `bad` set keeps one replacement rule instead of a copy. The gate
   harness says the bar-death "screening record names the world, episode and member", so it is
   recorded in `ScreeningRecord`. Both additions are no-ops by default. `smoke_variant`'s
   cheaper record (see above) is a speed fix with an equality test.
2. **The two-wave screen always prunes.** In wave 2 only W2's members have rows, so X / Y with
   the unpruned roster would lack rows for the non-W2 members on `ws_wide`. D3 makes pruning
   step 5 of the screen. So `--member-waves v3` prunes without `--prune`, and the pins record
   `prune: true`.
3. **`--worlds-per-family N` = the first 2N calm and N shocked gate worlds per family**, not "1
   world per family".
   - A dry-run scope is a `Registry`, which enforces gate-harness "Regimes" (calm ≥ 2 × shocked
     per size). A scope with one world per family can hold no shocked world (calm-00 sorts
     first), and a shocked-only scope is refused by the registry.
   - The 2 : 1 cut is the smallest that includes shocked worlds, which the smoke profile needs.
4. **The smoke picks its 6 members with `--members`, not `--max-members 6`.**
   - The first 6 draft members by id are `always_both` × 6 routers. At horizon 12 they deliver
     0 units on every world.
   - Zero-baseline replacement then exhausts every reserve and the screen fails (observed:
     "no usable reserve left").
   - The smoke uses six named members instead: EP × RR / prop / MS / MWW, stock_aware/prop and
     always_both/even_split.
   - `--episodes-per-world 1` keeps it under 2 min.
5. **`--shock-profile` is a new dry-run flag.** The gate CLI had no way to put a screen's
   shocked worlds in their smoke form. It accepts only `shocks-i-smoke` and only with
   `--dry-run`, and it is pinned.
6. **Reserves on demand only.** `eager` is refused for the two-wave screen: each wave's reserves
   depend on that wave's roster. `none` stays a dry-run option.
7. **The routing reading's producer is `entity_planner`.** The spec says "the best producing
   baseline"; D3's rule says `entity_planner`. I followed D3, which also matches the 11-router
   pilot roster.
8. **Floor undefined on one shocked episode.** D3's shocked floor needs ≥ 2 episodes. With one
   (a filtered dry run) the floor is `None` and the world does not count. It is never counted on
   the 0.05 cut alone.
9. **The v2-roster bar** reads the frozen `roster_v2.json` members on each final v2 world, from
   wave-1 rows. It is skipped when a v2 member did not run (filtered dry runs).
