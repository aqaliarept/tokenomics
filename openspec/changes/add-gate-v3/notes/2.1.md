## What changed

- **`/srv/research/tokenomics/tokenomics/tokenomics/eval/world_space.py`.** Everything is added
  after `sample_worlds`; no existing function changed.
  - `GATE_V3_SPLITS = ("development", "sealed")` and `gate_v3_stream(split)`, which returns
    `"gate-v3-<split>"` and refuses any other split. 2.2 should take its stream names from here.
  - `region_sample(stream, size, n, *, choice, shocks, pattern, shock_rate=1.0,
    hit_magnitude=0.45, outage_duration=3, shock_window=SHOCKS_I_WINDOW) -> list[WorldPoint]`.
    - World i takes its six continuous levers (`k_c`, `m_q`, `capacity_scale`, `h_cap`,
      `h_deg`, `h_cost`) from row i of `lhs_columns(stream, size, n)`, mapped exactly as
      `sample_levers` maps them.
    - Choice, shocks, pattern and the three shock levers are the caller's. The hypercube's
      categorical columns and its shock-lever columns are ignored.
    - The seed is `world_seed(stream, size, i)` and the pattern parameters are
      `pattern_params(pattern, seed)`. Both are the same as `sample_worlds` on the same stream,
      so the continuous levers and seeds of a region sample equal the atlas sample's row for
      row.
    - The fixed levers are validated once with `check_levers`, so a choice the size lacks, an
      out-of-range shock lever or an unknown pattern is refused.
    - The points are plain `WorldPoint`s (atlas field = the stream name), so `world_record`,
      `point_from_record` and `config_from_record` work on them unchanged.
  - `check_shock_profile(name, *, levers, cfg=None)`.
    - It refuses any name other than `"shocks-i"`. That includes `"shocks-i-smoke"`.
    - It refuses `"shocks-i"` unless shocks are on, the shock levers are neutral
      (1, 0.45, 3) and the pattern is `drift`. Missing levers count as neutral, which means
      shocks are off, so that case is refused too.
    - When it is given `cfg`, the built world's shock generators (sorted by kind) and its demand
      drift must equal `apply_shock_profile(cfg, load_shock_profile("shocks-i"), P)`. A
      `shock_window` other than (21, 90) therefore fails, because the start windows differ.
  - One paragraph was added to the module docstring.
- **`/srv/research/tokenomics/tokenomics/tokenomics/eval/task_archive.py`.**
  - `_world_space(seed, shock_profile=None, **params)`. With no `shock_profile` the code path is
    unchanged: it calls `build_world(seed, **params)`.
  - With a `shock_profile`, it checks the name and levers before building, then compares the
    built generators and drift. The profile only names the world; the levers still build it,
    so the config and its hash are the same with or without the param.
  - The reproducer comment now lists the param.

## Gotchas for 2.2

- **ws_loaded's alternating choice.** One `region_sample` call has one fixed choice. For
  `ws_loaded`, build two samples on the same stream (`dense` and `sparse_f4`, same n = 128).
  They share every seed and continuous-lever row, so for draw index k take the point from the
  sample whose choice matches the slot being filled. ρ depends on the choice, so measure it on
  that point. Consume each index once, in index order, so that no seed is used twice.
- **The generator ref.** `WorldPoint` does not carry the profile name; that was kept out to
  leave the point / record format byte-identical. For shocked region entries 2.2 writes
  `{"generator": "world_space", "params": {"producers", "levers": point.levers.to_dict(),
  "shock_window": list(point.shock_window), "shock_profile": "shocks-i"}}`. Calm entries omit
  `shock_profile`. The reproducer then enforces the shocks-i equality on every replay, so the
  registry's "kinds equal shocks-i" validation can be a replay plus
  `world_space.check_shock_profile`.
- **BINDING carry-forward for 2.2 / 3.1: shocked region worlds have no valid smoke form yet**
  (review round 1, concern 1; 2.1 keeps its letter, "accepts only `shocks-i`").
  - Today, a shocked neutral-lever drift world under the `world_space` reproducer is refused
    in all three forms:
    - `shock_profile="shocks-i"` with `shock_window=SMOKE_START_WINDOW` (the generators' start
      windows differ);
    - `shock_profile="shocks-i-smoke"` (refused by name);
    - no `shock_profile`, because `registry.py:300-304` (`_check_shock_profiles`) refuses a
      v2+ shocked entry that names no profile.
  - So a v3 registry cannot hold a horizon-12 smoke of a shocked region world. Task 3.1's verify
    ("`--dry-run --horizon 12` with `shocks-i-smoke`, 1 world per family") needs one.
  - The round-0 workaround in these notes ("drop `shock_profile`, set the window") is
    **withdrawn**. It breaks that registry rule and hides the smoke from
    `gate_cli.test_only_problem`, the guard that keeps test-only profiles out of real runs.
  - **Required before the 3.1 smoke.** The supervisor puts it in 2.2 (or 3.1) and approves the
    change to 2.1's letter.
    - `world_space.check_shock_profile` / the `world_space` reproducer also accept
      `"shocks-i-smoke"`, on a world with `shock_window == SMOKE_START_WINDOW`.
    - It is checked against `smoke_profile(load_shock_profile("shocks-i"))`: generators equal,
      and drift equal to `shocks-i`'s.
    - Every other name stays refused, including `"shocks-i"` with the smoke window.
    - `names_test_only_profile` then flags the ref, so `test_only_problem` keeps it to
      `--dry-run`.
    - Tests: the smoke ref replays; a smoke ref in a real run is refused; `shocks-i-smoke` with
      the (21, 90) window is refused; and the existing refusals stay.
