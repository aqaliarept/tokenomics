## What changed

### `/srv/research/tokenomics/tokenomics/tokenomics/eval/registry.py`

**Constants**
- `EXCLUDED` was added to `STATUSES`.
- `WS_LOADED`, `WS_WIDE` and `REGION_FAMILIES` are new. `FAMILY_GENERATORS` maps both region
  families to `world_space`.
- `GATE_FAMILIES_V3` is new. `GATE_FAMILIES` is unchanged and still drives v1 / v2.
- `FAMILY_SIZES`: `sparse_wide` 12 and 42, `ws_loaded` 12, `ws_wide` 42.
- `REGION_CHOICES`, `REGION_POOL = 128`, `RHO_BAND = (0.28, 3.1)` and `REGION_WORLD_COUNTS`
  hold the D2 values.
- `M4_TRAIN_STREAM = "m4-es-train-v1"` and `M4_RESERVED_INDICES = 4096`.

**`WorldEntry.region`**
- A new optional field: `{"pool": n, "record": world_space.world_record(point)}`, set on
  region entries only.
- It is omitted from the payload when it is None, so v1 / v2 entries serialize and hash as
  before.

**`Exclusion(family, size, headroom)`** and **`ScreeningRecord.exclusions`**
- `exclusions` is omitted from the payload when it is None.
- `ScreeningRecord.excluded()` returns the excluded (family, size) pairs.

**`Registry.validate`**
- `_check_region_seeds()` runs first, so that a seed clash names its source. It checks region
  world seeds by explicit sets:
  - development against sealed, naming both entries;
  - every region world seed **and episode seed** against `region_reserved_seeds()`, naming the
    holder (e.g. "atlas world ws-atlas-v1-12-0111").
- Per entry:
  - A v1 / v2 registry holding a region family, an `excluded` entry or a region record is
    refused.
  - v3 refuses the legacy `dense` family.
  - Region entries go to `_check_region_entry`. Legacy entries keep the range check, the
    per-family cross-split check and `_check_generator`, unchanged.
- `_check_region_entry` checks:
  - the family's size;
  - a `world_space` generator ref whose params are exactly {producers, levers, shock_window},
    plus `shock_profile` on shocked entries (required, as the v2+ rule already demands);
  - canonical levers that pass `check_levers`;
  - the family's choice;
  - calm worlds: shocks off and the cyclic pattern;
  - shocked worlds: `check_shock_profile(name, levers, shock_window)`;
  - a region record `{pool, record}` whose stream, size, seed, generator version, levers and
    window describe this entry;
  - that the record's index is draw `index` of `region_sample(gate_v3_stream(split), size,
    pool)` with the entry's fixed levers (the seed and levers are re-derived);
  - that the recorded ρ lies in (0.28, 3.1].
- `_check_exclusions` checks:
  - exclusions exist only from v3 on, and only on a screened registry with a headroom record;
  - each exclusion equals a **failed** recorded headroom result for its family × size, and there
    are no duplicates;
  - every entry of an excluded family × size, in both splits, gate and reserve, is `excluded`;
  - every `excluded` entry belongs to an exclusion.

**`check_replay`**
- For region entries, the replayed config's `config_digest` must equal the record's
  `config_sha256`, and the error names the entry.
- Shocked region entries replay through the `world_space` reproducer, which enforces the
  `shocks-i` equality.

**`coverage_problems(sizes, gate_families=None)`**
- v1 / v2 behave as before: the default is `GATE_FAMILIES` and the messages are the same.
- From v3:
  - the default is `GATE_FAMILIES_V3`;
  - each family is required only at its `FAMILY_SIZES`;
  - an excluded family × size is not required;
  - the message says "registry v3" instead of "M1".

**`admission_problems`**
- A failed headroom result with a matching recorded exclusion is no longer a problem.
- A failed result without one is still refused.

**New functions**
- `_region_draw`: a cached `region_sample`.
- `_registry_file_seeds`: the seeds of a packaged registry file, read without replay but with
  the hash checked.
- `region_reserved_seeds()`: cached; maps each seed to its holder.
- `region_entries(split, family, pool)`, `draft_worlds_v3()` and `build_worlds_v3()`.
- `write_acceptance`.
- `smoke_variant(entry)`.
- `record_exclusions(registry)`.

**CLI**
- `--draft-version 3` writes the registry to `--out` and `acceptance.csv` beside it, then
  reloads the written file (hash check and replay).
- For v3 it refuses an `--out` inside the packaged registry directory.

### `/srv/research/tokenomics/tokenomics/tokenomics/eval/world_space.py`

`check_shock_profile(name, *, levers, shock_window=None, cfg=None)` is the binding smoke form from
the carry-forward.
- It accepts `shocks-i` and the test-only `shocks-i-smoke`.
- With `shock_window` given, `shocks-i` needs (21, 90) and `shocks-i-smoke` needs
  `SMOKE_START_WINDOW`.
- With `cfg` given, the generators and drift must equal `apply_shock_profile(cfg,
  load_shock_profile(name))`. For the smoke name that is
  `smoke_profile(load_shock_profile("shocks-i"))`, which keeps `shocks-i`'s drift.
- Every other name is refused.

## Departures from the task text / sources (each for the reviewer)

1. **A new `WorldEntry` field (`region`).** The task says "each region entry carries its world
   record", but `test_registry_v2::test_world_entry_type_is_unchanged` pinned the field set.
   - I added one optional field and amended that test.
   - I did not put the record in the generator ref: the ref feeds the reproducer and must stay
     `{generator, params}`.
   - I did not use a registry-level side table either: a record keyed away from its entry is
     easier to lose in copies and replacements.
   - The field is omitted when None, so v1 / v2 payloads and hashes are byte-identical (frozen
     versions tested).
2. **The record also stores the hypercube `pool`.** The draw is `lhs_columns(stream, size, n)`
   row `index`, and those rows depend on n (world-space "Region samples": a function of
   (stream, size, **pool size**, fixed levers)). So validation needs n to re-derive the draw. The
   world record itself is `world_space.world_record` unchanged.
3. **The reserved set is wider than tasks.md lists.**
   - tasks.md lists "every v1 / v2 world and episode seed, every atlas-v1 sample / anchor seed
     and the first 4,096 `m4-es-train-v1` seeds".
   - I also reserve the atlas-v1 screen and confirm **episode** seeds, and the whole EXP-0050
     fanout grid with its episode seeds; the grid is the anchors' source, so it is a superset of
     the 8 anchors. This matches my 2.1 note and `order_es_worlds.reserved_seeds()`.
   - I check region **episode** seeds against the set as well as world seeds.
   - It is stricter, and the draft passes it with 0 collisions.
4. **Refusals happen at construction, not only at screen / report admission.**
   - A region family, an `excluded` entry or a region record in a v1 / v2 registry is refused
     when the `Registry` is built. That covers load, as tasks.md asks ("refused on load").
   - The spec's "Region family in a v2 registry" scenario only asks for a refusal at a real
     screen or report; construction is stricter.
   - The legacy `dense` family is refused at construction in v3 ("The legacy dense family is
     refused"). v1 / v2 dense handling is unchanged: it is constructible and flagged by
     `coverage_problems`.
5. **A separate `_check_region_entry` instead of extending `_check_generator`.** tasks.md says
   "`_check_generator` accepts `world_space` for region families". The behaviour is the same;
   the region schema lives in its own method, so the legacy method's code and messages stay
   byte-identical.
   - `shock_profile` is required on shocked region entries (the existing v2+ rule) and refused
     on calm ones.
   - Its accepted values are `shocks-i` and, per the binding carry-forward, `shocks-i-smoke`.
6. **The smoke form is approved and binding.**
   - `check_shock_profile` gained the `shock_window` pre-check.
   - `smoke_variant(entry)` is new. It builds the dry-run form with its own world record, because
     the smoke window changes the config hash, so the old record would fail replay.
   - The withdrawn workaround (dropping `shock_profile`) is not used anywhere.
7. **The slot order across regimes is my reading.**
   - Within one (split, family) pool the calm slots draw first, then the shocked slots, each in
     the order gate worlds then reserves, consuming indices in order. D2 fixes "index order" and
     the ws_loaded alternation ("by slot index within each (split, regime) group, gate worlds
     first, then reserves"), but not which regime draws first. I used `REGIMES` order
     (calm, shocked).
   - A rejected index is consumed and never retried by another slot. ρ depends on the choice and
     regime, so a draw rejected under one slot's choice is not offered to the next slot, which
     would give the same seed two chances.
8. **`acceptance.csv` has extra columns.** The task names (draw index, slot, ρ, accepted). The
   file also carries split, family, size, regime, choice, seed and the accepted world id, so
   every row is self-describing.
9. **`record_exclusions` is an addition.** It is a pure helper for D3 step 4 that 3.x's screen
   will call; tasks.md 2.2 only requires the status, the record and the admission handling.
   Exclusions are derived only from recorded failed headroom, so they cannot disagree with it.
10. **Not done here**, since they are outside 2.2's text:
    - D2's `small_sample` flag (a D4 X / Y matter);
    - bar-death replacement and the per-(split, size) sealed screening record (3.x / D5).

## Gotchas for 3.x

- `twin_params` and `gate_cli.test_only_problem` already work with region refs: the smoke variant
  is flagged, and `load_shock_profile("shocks-i-smoke")` resolves.
- A dry run on shocked region worlds should call `registry.smoke_variant(e)` per entry. Do not
  hand-edit the ref; the record must match the smoke config.
- `record_exclusions` follows `record_headroom`. Exclusions must be fixed before W2 is built
  (D3).
- `_region_draw` and `region_reserved_seeds` are process-level caches. Tests that monkeypatch
  `gate_v3_stream` change the stream name, which is part of the cache key, so they are safe.
- Commit timing: package source hash moves (carry-forward "Commit timing vs M4").
