# 6.1f: `order_es_validate` reads runs trained under pre-registration v2

Base e35c4a6, not committed. `train/` is unchanged between e35c4a6 and 83161ba (gate-v3 3.1).
Source: tasks.md 6.1f, prereg v2 `511e939a…`, design D7. Only `train/order_es_validate.py` and
its test file were touched. `order_es.py`, gate-v3 files, `per_order_scorer.py` and
`env/agent_history.py` are untouched.

## What decides stays unchanged

v2 changed training only: minibatch 24, the noise margin, and the A1-S2 probe arm. Its
`readings` section, which holds every D7 validation clause, floor, label and the power rule, is
byte-identical to v1's and equal to the code's `readings_registration()`. A read applies the same
clauses under either file, and `analyse` has no version branch. The margin never reaches a
validation clause; D7's run-down / starvation row-share clauses are unchanged.

## Changes (`order_es_validate.py`)

- **The frozen files a read accepts.** `FROZEN_PREREGS = {v1 b9d449c1…: 1, v2 511e939a…: 2}`.
  - `real_run_problems` accepts either file.
  - A run must be trained under the read's own file: `c.prereg_sha256 != prereg_sha` is
    refused. Under a v1 read this is the old check, with the same message.
- **`prereg_read_problems(doc)`** compares a doc against `registered_sections(version of the doc)`
  plus `readings`. For a v1 doc that is the old comparison.
- **The v1 / v2 mix refusal, in every mode** (dry runs too), before any job and before any
  output file.
  - A run's version comes from its training pins (`disqualification.prereg_version`, which
    `order_es._v2_pins` writes; none means v1).
  - The read's version comes from the file's SHA, or from its format for a non-frozen dry-run
    file.
  - Any run whose version differs from the read's is refused: "pre-registration mix: run X was
    trained under vN, this read uses vM (--prereg)".
- **`--mode recompute`** refuses runs whose version differs from the read's pinned file.
- **`--mode power`** takes `--prereg`, default v1. It refuses a non-frozen file and pins the
  file's SHA. The rule (`readings.power_rule`) is the same under both, so the records differ
  only in `prereg_sha256`.
- **`--reuse-references` / `--seed-combine` need no new code.** `REUSE_PINS` already includes
  `prereg_sha256`, so a seed-1 read must use the seed-0 read's file. With the mix check, the
  seed-1 run is also trained under it. Cross-version reuse is refused in both directions
  (tested).
- **`--prereg` stays default v1**, so v1 behaviour and CLI are unchanged. A v2 read must pass
  `--prereg …/es_prereg_m4_v2.json`; forgetting it is refused as a mix. tasks.md 7.3 / 7.5
  commands now pass it.
- `Candidate` gains `prereg_version` (default 1). No pin, spec key or output column is added,
  so a v1 read's files are unchanged.

## Tests (`tests/test_order_es_validate.py`)

- **Fixture `v2_runs`:** three dry runs (A1-s0, A2-s0, A1-s1) trained under v2 on the same
  2-world bar. Their pins carry `prereg_version` 2 and the v2 SHA.
- `test_both_frozen_files_decide_alike`:
  - v1 and v2 `readings` are equal to each other and to the code's;
  - each file passes its own section check;
  - a v2 file with v1's `es` section, or with a changed reading, is refused.
- `test_v2_trained_runs_validate`:
  - a v2 read plays, reads (`valid`) and recomputes (MATCH);
  - as a real read it raises none of the pre-registration refusals.
- `test_prereg_mix_refused`:
  - v2 runs under v1, v1 runs under v2, and a mixed pair (naming only the v2 run) are all
    refused, with no `episodes.csv` written;
  - recompute refuses a read whose pins name the other version.
- `test_seed_combine_under_v2`:
  - v2 seed-1 reuses a v2 seed-0 read;
  - a v1 seed-1 read cannot reuse a v2 seed-0 read, and the reverse also fails, both with
    `other pins: ['prereg_sha256']`.
- `test_power_under_either_frozen_file`: identical records except the pinned SHA; a non-frozen
  file is refused.

## Folded in (supervisor, after EXP-0069's erratum)

- **The probe record's noise label.** `order_es.py` now writes `"purpose": f"probe|{base_arm(a)}"`
  in `probe.json`'s `noise` block.
  - A future A1-S2 probe records A1's stream, which is the one it plays.
  - v1 has no σ arm, and `base_arm(a) == a` for A1 / A2, so v1 output is unchanged.
  - Pinned in `test_v2_probe_and_train_dry_runs`: v2 gives A1 → `probe|A1`, A2 → `probe|A2`,
    A1-S2 → `probe|A1`; v1 gives exactly `probe|A1`, `probe|A2`.
  - `probe_from_rows` never reads this block, so EXP-0069's offline recompute is unaffected.
- **The `next` text of `weak` is left unchanged, and here is why.**
  - The text is "minibatch 24; pilot and main runs re-sized and launch-fit-checked". It is
    v1-worded: under v2, 24 is already the base, so nothing is re-sized.
  - The change would be a one-liner (branch on `minibatch is None`).
  - But `probe_reading`'s output is part of what `probe_from_rows` recomputes. Changing it now
    would make the recompute of EXP-0069's committed `probe.json` differ in `reading.next`,
    breaking the record's MATCH.
  - So the supervisor decides. Options: change it, accepting that EXP-0069's `next` stays the
    old wording, recorded as such in its RESULT; or leave it, since `step_next` already says
    "minibatch 24 suffices; pilot at sigma". I recommend leaving it.
