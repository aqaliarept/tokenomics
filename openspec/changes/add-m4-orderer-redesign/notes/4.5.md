# 4.5 — `eval/split_need.py`, the EXP-0066 split-need re-test driver

## What changed
- New `/srv/research/tokenomics/tokenomics/tokenomics/eval/split_need.py`: task 4.4's probe
  (`probes/split_need.py`) ported into a pod-runnable driver, built like `decoder_check`.
  - **Sample**: `decoder_check.select_views` (23 + 14 worlds) at every confirm seed
    (`world_entry`): 71 world-episodes. Arms TS and MWWk via `decoder_check.decoder_arm`
    (R = 2, EXP-0057's subjects and replicate seeds). Every job sets
    `job_draw_key(job)`. That gives 284 jobs.
  - **Worker** (`run_split_job`): `run_decoder_job`'s path (`joint_stack_env` → `set_draw_key` →
    `RoutingTracer` → `ContractMonitor` → `decoder_policies`) plus `SplitNeedObserver`, attached
    after the tracer, as in 4.4. Rows = gate columns + `trace_*` + `arm` + 57 `sn_*` cells:
    - per count (joint / L / P / units) × stream × class, units and orders;
    - `sn_lost_total_*`, `sn_classified_rejections_*`;
    - self-check counters `sn_replay_mismatch` / `sn_dup_bids` / `sn_qty_mismatch`;
    - info counters `sn_nonuniform_sheets` / `sn_outage_candidates_excluded`.
  - **Pure classification**, pulled out of the observer so it can be tested by hand:
    - `LostBid`, a frozen dataclass: per eligible producer, need and per-unit sheet;
    - `per_order_classes`: L / units / P, unchanged from 4.4;
    - `joint_classes`: the yardstick. Bids go in descending price order; choice goes to the
      first eligible producer that fits; a split takes each type greedily.
    - The L pool keeps 4.4's raw sum of leftovers (`_pool(clip=False)`). Joint and P clip
      negatives to 0, as in 4.4, so the port reproduces 4.4 exactly.
  - **Reading** (`split_reading`; it computes with `Fraction`, so 5% is an exact edge):
    - deciding arm MWWk, TS reported;
    - per size: Σ corrected / Σ `units` over the size's MWWk rows (world-episodes × replicates),
      where corrected = `sn_joint_consumer_split_units` × completion and completion = (units +
      wasted) / (units + wasted + failed dropped / ttl / ttl_outage), 4.4's formula, from the
      run's own row;
    - `split_needed` if the share is ≥ 5% at any size, else `whole_suffices`;
    - `incomplete` only if a size has no MWWk row or no filled units and no other size fires;
    - `next` gives the pre-registered consequence.
    - Reported in `reading.json`, never deciding: TS's pooled block, the uncorrected joint / L /
      P / units shares, and the class sums.
  - **Validity → exit 2** (`CONTRACT_INVALID`):
    - contract failures, missing rows, digest differences (`execute`);
    - `consistency`: in both streams, every count's classes must sum to the traced
      `trace_lost_units_*_no_fit`, `sn_lost_total` must equal it, and the three self-check
      counters must be 0 (check `split_need_consistency`);
    - `neutrality` against EXP-0057: the same cell set as 4.4 (units, dead, digests,
      `shock_events`, `fulfilled_trace`, ordered / fulfilled units and every scalar `trace_*`
      cell; 79 cells on real rows) for every row (check `exp0057_neutrality`; a digest
      difference is `digest_pairing`).

    An invalid run withholds the reading (`decoder_check.withheld_reading`).
  - **Fail-fast**: a reference that lacks any pinned (world, episode, subject, replicate) key is
    refused before any job or spec is written.
  - **Real run** needs:
    - atlas content hash `220886a7…`;
    - orderer `d25388bf…`;
    - EXP-0057 `episodes.csv` SHA-256 `69656f9e2034…` (registered as `EXP0057_EPISODES_SHA`);
    - horizon 100, a 40-hex commit, no filters, and the 23 / 14 sample.

    `--dry-run` allows `--worlds --max-worlds --arms --horizon --shock-profile shocks-i-smoke`;
    the reference is optional there.
  - **Outputs**: `spec.json` (pins incl. the reference path + SHA-256, the pre-registered block
    with rule, threshold, deciding arm and `next`), `episodes.csv`, `split_need.csv` (per row),
    `split_need_worlds.csv` (per world × arm: joint and L classes, pooled completion, corrected
    units, shares corrected / joint / L / P / units), `neutrality.csv`, `reading.json`,
    `contract_failures.csv`, `RESULT.md` skeleton (question, the rule verbatim, TODOs).
  - **Resume**: same `--out-dir` with equal pins continues (tested: "8 already done, 0 to run").
- New `/srv/research/tokenomics/tokenomics/tests/test_split_need.py`, 10 tests.
- New probes (outside the package):
  - `/srv/research/tokenomics/openspec/changes/add-m4-orderer-redesign/probes/timing_45.py`
    times `run_split_job` per job and checks neutrality and consistency;
  - `probes/timing_45.jsonl` holds the 8 timed rows;
  - `probes/extrapolate_45.py` prices the real 284-job list with 2.3's pool model.
- `/srv/research/tokenomics/openspec/changes/add-m4-orderer-redesign/sizing.md`: new §EXP-0066.
- `/srv/research/tokenomics/CLAUDE.md`: an "Evaluation" bullet, "Split-need re-test
  (EXP-0066)", after the decoder-check bullet.
- Not touched: `domain/`, `env/`, `decoder_check.py`, `routing_*`, the goldens, the registry /
  roster / params files, `tasks.md`, and task 5.1's files. Not committed.
