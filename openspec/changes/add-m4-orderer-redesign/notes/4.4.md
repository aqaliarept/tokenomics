## Method
- **Observer, read-only, outside the package.**
  - Each producer's `produce` is wrapped per instance and re-wrapped after every `reset`.
    Before the call the wrapper copies `capacities` and the placed bids. After it, it reads the
    `ProductionResult` and `reservations`. It writes nothing back and draws nothing.
  - `System.complete_cycle` is wrapped outside the RoutingTracer's wrapper.
  - Capacity state is read only by this diagnostic; no policy sees anything.
- **Auction budget B_j** (`produce`'s `auction_budget`, against which `no_fit` is decided):
  - Start from the capacities at `produce` entry.
  - Subtract the capacity held through the auction: the reservations after `produce` minus the
    ones created by this cycle's accepted bids, plus the carried reservations assembled this
    cycle (completed bids not accepted this cycle).
  - TTL-failed reservations freed theirs, as in `produce`.
- **Leftover L_j** = B_j − the capacity of the bids j accepted this cycle.
- **Consistency**: a replay of the price-greedy auction over B_j must reproduce the accepted /
  rejected bids and the outage / `no_fit` / `displaced` reasons exactly. Mismatches: 0 in all
  20 runs. The first draft omitted the assembled reservations and got 63 mismatches on 12-0060;
  this check caught it.
- **Which loss, which auction.**
  - Each order's last rejected / failed outcome is kept exactly as
    `RoutingTracer._after_auction` keeps `last_reason`.
  - At an unfulfilled order resolution whose last reason is `no_fit`, the lost units
    (`quantity − completed_qty`, which is `trace_lost_units_*_no_fit`) go to the class of that
    last `no_fit` bid. The bid is classified at its own auction (cycle t, chosen producer i).
  - `consumer` = consumer orders. `producer` = replenishment + investment orders
    (`routing_trace.order_class`).
- **Eligible set E**: producers declaring the product (`produces`). Outage producers are
  excluded, since they accept nothing and cannot be receivers (outage candidates excluded are
  counted in the report). On every classified bid the eligible producers' process sheets for
  the product are identical (`non-uniform eligible sheets 0`), so "the per-type requirement" is
  well defined.

## Counterfactual (primary L) and its bias
- **choice-fixable**: some j ∈ E, j ≠ i, has L_j ≥ R on every recipe type, where R = the sheet ×
  q. The whole sub-order fits in what j's own auction left in that cycle, given the bids j
  actually accepted. Sending it there would have displaced nothing.
- **split-needed**: no single j qualifies, but Σ_{j ∈ E} L_j ≥ R per type (task definition; i's
  own leftover included).
- **unfillable**: not even together.
- **Why L**: it is the simple, conservative counterfactual. A receiver only gets capacity it
  left unused, so a "fixable" verdict needs no displacement and no assumption about where the
  displaced bids would have gone.
- **Bias and limits, with direction:**
  - *No displacement (L vs P).* L understates what a single producer could take, since an
    inserted higher-priced bid could have pushed out j's cheaper accepted bids. Sensitivity
    **P** inserts the bid at j's price: j's budget = B_j − its accepted bids priced ≥ the bid's
    price (ties go first). P moves units from unfillable / split to choice. On the reading
    worlds it moves unfillable → choice only (12-0111 289 → 128, 12-0344 56 → 0). On the
    context worlds it lowers split by ≤ 28 points (12-0352 117% → 90%). P ignores that the
    displaced bids are then lost.
  - *Independence.* Each lost bid sees the full leftovers, so concurrent `no_fit` bids
    double-count the same spare capacity. This **overstates** both choice and split. Sensitivity
    **joint**: a cycle's `no_fit` bids (both streams), in descending price order, claim the
    leftovers they are assigned to. Choice goes to the first fitting producer in declaration
    order; split takes per type, greedily. On the reading worlds it changes nothing. On heavy
    worlds it matters a lot: 12-0352 117% → 14.7%, 42-0081 38.5% → 5.9%, 42-0043 9.2% → 4.0%.
    Joint is conservative for choice-fixable + split-needed **together**, not for split-needed
    alone. Once an earlier bid has taken a producer's leftover, an order rated choice-fixable
    per order can become split-needed: 12-0230 411 → 423, 42-0126 0 → 49 (0% → 7.7%).
    - Overlap drives the gap (reviewer's count on 12-0352): 101 cycle × product groups hold
      choice / split losses.
    - In 35 of them, the lost orders' combined need exceeds the producers' combined leftover.
      Those 35 hold 1,102 of the 1,905 units.
    - In the worst group, 11 orders compete for a pool that covers 1/8.25 of their need.
  - *Per-type pooling.* The task's "together" test pools capacity per type. A real split hands
    whole sub-orders that must each fit atomically. Sensitivity **units** (Σ_j ⌊units j can
    take in L_j⌋ ≥ q) is ≤ the per-type test, so the per-type test **overstates** split-need:
    on the reading worlds by 0, on the context worlds by ≤ 23 points (12-0352 117% → 94%).
  - *Inputs.* Composite acceptance needs inputs; the counterfactual counts acceptance as a
    fill. This **overstates** both fixable classes, and on heavy worlds by a lot.
    - Per the reviewer, every lost consumer `no_fit` order on 12-0352 and 12-0111 is a
      composite product.
    - TS's completion share of accepted consumer bid units is 2–42% on the context worlds
      (table in §split-need), and 50–55% on the reading worlds 12-0060 / 42-0031.
    - Formula: (units + wasted) / (units + wasted + failed dropped / ttl / ttl_outage), from the
      EXP-0057 row. Bids still reserved at the horizon are left out.
  - *Static, one auction.* A fix would change later capacity, fund shares and reservations. The
    loss is attributed to the order's *last* `no_fit` auction, as the tracer attributes it; an
    earlier attempt (TTL 2) may have had more or less room (direction unknown).
- **Net for the rule.** On the reading worlds every variant gives 0 split-needed, so the reading
  is robust to these biases. On the context worlds the yardstick is joint. Under joint ×
  completion, only 12-0230 and 42-0076 stay ≥ 5%.
