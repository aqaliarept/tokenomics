# 4.2 — Agent-local history (design D5, ADR-0058)

Base commit 3c79900. Code navigation: the LSP tool is not available in this harness
(`ToolSearch select:LSP` finds nothing), so grep / sed were used.

## What changed

- New `/srv/research/tokenomics/tokenomics/tokenomics/env/agent_history.py`.
  - `AgentHistory`: per (ordering agent id, producer) state, holding 5 EMAs, raw totals since
    reset, latency and the last routed cycle.
    - `observe_owners(system)` runs just before `complete_cycle` and records which agent's
      `incoming` holds each open order.
    - `fold(cycle, result)` runs after `complete_cycle`. It reads only each `BidOutcome`'s
      `outcome` kind, `producer_id`, `order_id`, `quantity` and `routed_cycle`.
    - Readers: `features(aid, pid)` (9-tuple), `rows(aid, pids)` ((n, 9) float64), `totals`,
      `pairs`, and `state` / `snapshot` / `digest` (canonical JSON, for byte comparisons).
  - `attach_agent_history(env)` is opt-in. It installs callable hook *objects* (not closures) on
    `env.reset` and, at each reset, on `system.complete_cycle`, then exposes
    `env.agent_history`. Because the hooks are objects, a deepcopy (fork) gets its own coherent
    history.
  - Helpers: `stream_producers(system, aid, producer_ids)` (the eligible producers of the stream
    product, in decode order) and `env_agent_id(env, agent)`.
- **Additive `domain/` change** in `/srv/research/tokenomics/tokenomics/tokenomics/domain/system.py`:
  `BidOutcome.routed_cycle: int = 0` (last field, with a default), filled from
  `bid.routed_cycle` in `complete_cycle`'s `outcome()` helper and in the TTL-failure outcome of
  reservations whose parent order expired.
  - Why it is needed: completion latency = completion cycle − routed cycle. The routing cycle of
    a completed reservation is not in the per-cycle result.
  - The env-side alternative was rejected. It would match a completion to an earlier
    acceptance by (producer, order id). That is ambiguous when one order holds two reservations
    at the same producer, which happens when a split order's rejected remainder is re-bid to a
    producer that still holds the first part.
  - The domain already stamps `Bid.routed_cycle` and dates the telemetry's latency from it.
  - The change is pure data: no RNG, IO or logging. Nothing in the simulation reads it.
    Positional 8-argument constructions (tests) still work.
- New `/srv/research/tokenomics/tokenomics/tests/test_agent_history.py` (14 tests, ≈ 12 s,
  ≈ 630 MB peak with torch).
- Not touched: `aec_env.py` (the history is opt-in through the hooks), goldens, registry files,
  design / tasks text.

## Definitions (module docstring; supervisor addition 2)

- **Agent** = the domain ordering-agent id (the joint-stack stream `(source, product)`, e.g.
  `c0__20`). It is a key only.
- **Ownership.** An outcome belongs to the agent whose `incoming` held its order just before
  `complete_cycle`. An order keeps its holder for life. The owner map is pruned on
  `order_resolutions`.
- **Kinds.** `accepted`, `completed`, `failed` (dropped and TTL are one kind), `rejected` (every
  rejection is one kind). Routed units of cycle t = accepted + rejected units of cycle t.
- **EMAs** (features 0–4: routed, accepted, completed, failed, rejected units per cycle):
  `EMA = α·units + (1 − α)·EMA`, with α = the live system's `telemetry._alpha` (0.3), read at
  every reset. A pair starts folding at its first outcome and then folds 0 in every cycle
  without one (the telemetry's `_EmaSeries`).
- **Completion latency** (feature 5): the quantity-weighted EMA of (completion cycle − routed
  cycle) over completed sub-orders only. Failed and rejected sub-orders never enter it.
  - The first completing cycle sets it to that cycle's weighted mean, with no zero start.
  - Cycles without a completion hold the value (the telemetry's `_WeightedEmaSeries`).
  - Before any completion it is `NO_LATENCY` = 0.0. The completed EMA and the rate tell that
    case apart.
- **Completion rate** (feature 6): (C + 0.5·1) / (R + 1) over the raw totals since reset, i.e.
  a 1-unit prior at rate 0.5.
  - A never-routed pair gives 0.5.
  - Units still reserved count in R but not yet in C.
  - The design text says only "with a 1-unit prior". The prior *mean* 0.5 and the use of raw
    totals rather than EMAs are my choices (constants `PRIOR_UNITS`, `PRIOR_RATE`); flag them in
    review if another reading was meant. Raw totals keep the rate in (0, 1]. An EMA ratio is not
    bounded, because the completed EMA lags the routed one.
- **Log recency** (feature 7): log(1 + t − r), where t = last folded cycle + 1 and r = the last
  cycle with routed units. r = 0 if never routed, so the value is always ≥ log 2.
- **Never-routed** (feature 8): 1.0 if R = 0, else 0.0.
- **Timing.** The history only changes inside the fold hook, after the inner `complete_cycle`
  returns, and at reset. At cycle t's ordering it equals the state after cycle t − 1's fold.

## Gotchas for 4.3 (`train/per_order_scorer.py`)

- **Wiring.** Call `attach_agent_history(env)` once, before the first reset. Then
  `h = env.agent_history`, `aid = env_agent_id(env, agent)`, and
  `h.rows(aid, env.spec_.producer_ids)` gives (P, 9) in decode order. Read eligible rows through
  the action mask or `stream_producers`.
  - Read the history during the agent's turn. It is frozen for the whole ordering phase.
  - `aid` is a key only, never a model input.
- **The choice-v1 driver also merges `decode_pins`** (carry-forward). The history adds no env
  option, so no pin and no fingerprint change. A driver that uses history must still attach
  it, or the 9 features are absent.
- **Normalisation hints** for the fixed median / IQR:
  - **IQR = 0 is common.** `never_routed` is binary. `failed_ema` and the latency are 0 on most
    rows, and under TR most non-top producers have zero EMAs. Guard the division, e.g.
    IQR → max(IQR, ε), or pass binary features unscaled.
  - The EMAs are in units per cycle and scale with order quantity, so they are heavy-tailed.
    Consider `log1p` before median / IQR, and hash that choice with the normaliser.
  - `completion_rate` ∈ (0, 1], `log_recency` ≥ log 2 (grows like log t, ≤ log 101), latency ∈
    [0, ~2].
  - The normaliser is fitted on pilot rows, which are dominated by early-episode empty
    histories (rate 0.5, flag 1). Say so in the pre-registration.
- **Shared-only ablation** ("history replaced by the mean over the product's agents"):
  - Agents = every stream agent of the product: `[a for a, x in system.stream_products.items()
    if x == product]`. That includes agents that never routed, whose rows are the prior.
  - Take the feature-wise mean of `h.rows(a, pids)` over those agents, with the same producer
    columns. `never_routed` becomes a fraction.
  - Compute it from the same frozen history at the turn. It is then identical across the
    product's agents (the 4.3 test). Record whether never-routed agents are included. Excluding
    them changes the mean, and an empty set would need a rule.
- **Forks / teacher search**: the hooks are deep-copied coherently. The `RoutingTracer` closure
  is still the DIAGNOSTICS 22 issue. Attach order relative to the tracer does not matter: each
  wraps whatever `env.reset` / `complete_cycle` is current.
- **ADR-0058 test for 4.3** can reuse `test_earlier_ordering_agents_same_cycle_routing_is_invisible`'s
  replay pattern. Add φ / ψ / b_i / own-turn features to the compared dict.
- `BidOutcome.routed_cycle` defaults to 0 for hand-built outcomes. Real ones always carry
  ≥ 1.
