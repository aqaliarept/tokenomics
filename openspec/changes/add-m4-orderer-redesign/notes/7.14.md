## Mapping the task's classes onto what the domain exposes
Every class is determinable from white-box state, so no proposal-first stop was needed.
- **Snapshot:** at the start of `System.complete_cycle` (outside the tracer's wrapper). Bids are
  already placed then, and nothing changes until `produce`.
- **Bid shape:** a bid's capacity and input need is the producer's sheet × the bid's quantity
  (`ProducingAgent._to_bid`), so no per-producer wrapper is needed.

| task class | domain source | observer class(es) |
|---|---|---|
| (a) capacity-short | `no_fit`, `dropped` | `a_held` (fits current capacity, reservations held it), `a_degraded` (fits max only: restoration-fixable), `a_max` (exceeds max), `a_dropped` |
| (b1) no input order | `ttl` + no replenishment of the missing input by that producer live in [acceptance, failure] | `b1_not_ordered` |
| (b2) ordered, not delivered | `ttl` + such a replenishment exists; its own cause one level up | `b2_late` (delivered in the failing cycle, after assembly, or later), `b2_short` (delivered earlier, stock still short), `b2_unfunded` (never got a bid: the fund did not back it), `b2_lost_<reason>` (rejected upstream, by its last bid's reason), `b2_open` (in flight at the episode's end) |
| (b3) upstream unable | `ttl` + no other declarer of the missing input had `makeable_qty_now` ≥ 1 (and no outage) in any window cycle | `b3_upstream_unable` |
| (c) outbid | `displaced` (fit the auction budget; higher bids took it) | `c_displaced` |
| (d) outage | `outage`, `ttl_outage` (the tracer's rule) | `d_outage`, `d_ttl_outage` |

**Two deviations from the task's wording:**
- **(c) "no-fit with capacity and inputs present" cannot occur.** `no_fit` means the bundle
  exceeded the auction budget, so it is always (a). (c) is `displaced` only.
- **Added `b4_contention`.** In this case no input was short at the start of the failing cycle,
  and another assembly took the stock first. The task's list does not cover it; it is a
  production-choice cause.

**Precedence with several missing inputs:**
- b3 if any missing input is b3 (unsavable by buying);
- else b1 if any is b1 (the producer's own decision);
- else b2, with the first missing input's cause.
- `st_multi_missing` counts these units.

**Consistency (exit 2):**
- per reason, the classes sum to `trace_lost_units_consumer_<reason>`;
- the observer's own per-reason sums equal the tracer's;
- the counters `history_missing`, `unregistered_orders` and `qty_mismatch` are 0.

**Neutrality:** every MWWk row must equal EXP-0057's (`split_need.neutrality`: the gate cells and
every scalar `trace_*` cell).

**Per producer-cycle** (`producer_cycles.csv`):
- capacity ratio and input stock units;
- inbound units and fund granted (as the tracer reads it);
- restoration and upgrade orders placed / completed / rejected;
- replenishment units placed / delivered / rejected.

**Reading** (`reading.json`, task 7.15): pooled shares of lost consumer units per top-level group
(a, b1, b2, b3, b4, c, d, never_bid). The largest at 12 producers names the decision (the
`DECISION` table); a runner-up within 5 points reads `tie`.

## Found while mapping (b): `RESERVATION_TTL` is not the order TTL (affects EXP-0073)
- **The mechanism.** `domain/producing_agent.py` fails a reservation after
  `cycles_waited >= RESERVATION_TTL` (a constant, 2). The failed quantity is never re-bid
  (`Order.sub_failed`). Task 7.12 made only the order TTL configurable.
- **The effect.** In EXP-0073, at TTL 3 / 4, orders lived longer, but a producer waiting for
  inputs still had two cycles.
- **What it invalidates.** EXP-0073's "input-wait expiries barely fall → scarcity" does not test
  input waiting at all. Its retry gains, from `no_fit` / `displaced` re-bids, are unaffected.
- **Fixing it** is a domain change, a new task for the supervisor: `Configuration.ttl` would also
  set the reservation TTL, default 2, byte-identical.
