## Tracer columns (all prefixed `trace_` in episode rows)
| column | definition |
|---|---|
| `lead_concurrent_top_share_{consumer,producer}`, `lead_concurrent_groups_*` | EXP-0056's measure, computed from placed bids: lead = largest part (ties to the lowest decode index); groups = (class, cycle, product, eligible-index tuple), ≥ 2 eligible producers; slots < `k_stream` only; mean top share over groups of ≥ 2 orders |
| `share_swing_consumer`, `share_swing_pairs_consumer` | D9: per product with ≥ 2 declarers, TV between the producer shares of its consumer bid units in cycle t and cycle t − 1 (strictly consecutive cycles; re-bids count), weighted by cycle t's units |
| `concurrent_cross_agent_share` (+ `_pair_share`, `concurrent_groups`) | 1.3 (a), group version (the trigger's definition): of the ≥ 2-order same-cycle same-product groups on ≥ 2-declarer products, the share holding ≥ 2 agents; pair version beside it |
| `orders_per_turn_{consumer,producer}`, `active_turns_*` | orders / active turns (agent × cycle holding ≥ 1 order of that class) |
| `agent_history_dispersion`, `agent_history_cells` | D3 / 1.3 (b): median over (product, producer) cells with ≥ 2 agents routing ≥ 3 units of the population SD of completed / routed (all products) |
| `routed_share_dispersion`, `routed_share_pairs` | D3 / 1.3 (b): median pairwise TV of routed-share vectors; ≥ 2-declarer products, agents with ≥ 3 routed units |
| `routed_share_dispersion_producer_streams` (+ `routed_share_pairs_producer_streams`), `_vs_rest`, `_unit_weighted` | reported only, never a reading. These are the 1.3 review's alternatives, as its `rerun.py` computes them: producer-stream pairs only; each agent against the pooled units of the product's other qualifying agents; the weighted median of the pairs with weight = product of the two agents' routed units |

An "agent" is the (ordering agent id, product) stream, which is the joint_stack ordering agent.
An empty measure is 0.0; the count column beside it tells an empty value apart from a real 0.
This keeps the existing `all(v >= 0)` tracer invariant.

## Score fidelity (TS / TR), and how 2.2 reads it
- Wrap the *scorer*, not the arm:
  - TR: `order = ScoreFidelity(trained)`;
  - TS: `order = TRAINED_WRAPPERS["trained_sampled_whole"](ScoreFidelity(trained))`.
  Then `row.update(fid.cells())`. The wrapper changes no action (tested), and the scorer is
  still called once per turn.
- A decision is one slot order with ≥ 2 eligible producers. For each decision, with
  s = the scores over the eligible producers and m = their `makeable_qty_now`:
  - Spearman of s against m (the ranks of log m); skipped if s or m is constant;
  - top-1: the first argmax of s is one of m's argmaxes; skipped if m is constant;
  - KL(softmax(s) ‖ softmax(makeable_logits(m))). The second distribution is the scorer's own
    distillation target: log m clipped to ±10, −10 when m = 0, uniform when nothing is
    makeable. It is finite where a pure m / Σm share would give an infinite KL.
- Cells: `score_spearman_log_makeable` (median), `score_top1_agreement` (mean of 0/1),
  `score_kl_to_makeable` (median), with `score_spearman_decisions`, `score_top1_decisions` and
  `score_decisions`. An empty measure is `""`. For D3's medians pooled over episodes, read
  `fid.values["spearman" | "top1" | "kl"]` (per-decision lists).

## Gotchas for 2.2 (`eval/decoder_check.py`)
- **Set the key per job.** Call `set_draw_key(env, DrawKey(job["world"], job["episode"],
  job["replicate"]))` after `joint_stack_env(...)` and before `run_episode`.
  `routing_audit._run_job` does not do this. Through it, a TS / MWWk job raises inside the
  policy and becomes a job failure row (run invalid, exit 2). Either add the call to the job
  path (it is harmless for unkeyed routers) or give `decoder_check` its own `run_job`.
- **TS needs a decoder_check entry.** `routing_audit.job_policies` already wraps
  `job["ordering"] == "trained_sampled_whole"` around the trained scorer. `ScoreFidelity` must
  sit between the two (see above), so the driver needs its own `job_policies`.
- **TS's entry must give R = 2.** Add an arm-table entry like `split_arm`'s TW (`trained: True`,
  checkpoints pinned), but with `random: True` / `kind: stochastic`, or its own replicate count.
  Otherwise `build_jobs` makes one replicate. `ROUTER_KIND["mww_keyed"]` is already stochastic.
  The `action_seed` that `build_jobs` gives stochastic jobs is unused by the keyed draw; the
  draw uses `job["replicate"]`.
- **Paired keys.** TS − MWWk is paired only if both use the same `(world, episode, replicate)`.
  `episode` is the episode seed (`job["episode"]`), not an index.
- **Fidelity is per episode.** It comes only from the wrapper cells, which are not trace
  columns. D3 wants medians on visited states: decide whether to pool `fid.values` across
  episodes (e.g. a sidecar) or take the median of per-episode medians, and record the choice.
- **New `trace_*` columns.** Every driver's `episodes.csv` header grows. Old CSVs read fine,
  since columns are looked up by name; recorded EXP-0052 / EXP-0056 rows simply lack the new
  columns. Resuming an old out-dir is already refused by the source-tree pin.
- **Fingerprint.** `teacher_path_fingerprint` hashes every package `.py` whole, so EXP-0054's T
  reuse will now rerun T. This is expected; the registered value is EXP-0053's commit.
- **Dispersion reading.** The reading uses `trace_routed_share_dispersion` /
  `trace_agent_history_dispersion` (thresholds 0.10 / 0.05). The three extra columns are for
  EXP-0057's side-by-side table only (carry-forward). An empty measure reads 0.0; check
  `trace_routed_share_pairs` / `trace_agent_history_cells` > 0.

## Review round 1
1. **The permutation test could not see a leak inside the router's weights.** Fixed.
   - Cause: `_turn_inputs` recomputed the router's inputs itself, so those were identical by
     construction. The only behavioural check was the sampled producer, three draws in total.
   - Change: `_turn_inputs` now monkeypatches `routing_diagnostics.inverse_cdf` during the
     target's turn. It records every `(weights.tobytes(), u)` the router actually draws from,
     and these are compared byte for byte with the other inputs.
   - Re-check: the reviewer's mutants, re-implemented here, are now all caught by the
     obs-scorer test, which no longer needs the EXP-0012 variant:
     - M1: MWWk weights minus the same-product `p.bids` units;
     - M1b: avoid producers already bid on this cycle;
     - M2: TS scores − 0.3·len(p.bids).
   - Unmutated, earlier bids still differ in 9 / 9 (cycle, variant) cases for both routers.
2. **Equal `DrawKey`s could give different draws.** Fixed.
   - Change: `DrawKey.__post_init__` normalises integer types (e.g. numpy ints) with
     `operator.index`. It refuses a float, bool or str `episode` / `replicate` and a non-str
     `world` with a `TypeError`.
   - Test: `test_draw_key_is_strictly_typed`. Numpy ints equal the int key and draw the same;
     `1295251592.0`, `False`, `True`, `"1295251592"` and a non-str world are refused.
   - For 2.2: build the key from `job["world"]`, `int(job["episode"])` and `job["replicate"]`.
     A parsed CSV value must be converted to int first, or it is refused.
