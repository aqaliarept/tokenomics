## Definitions (all frozen in the prereg's `readings` section)

**Sample (D9).** Every atlas v2 validation world at 12 and 42 producers: 16 worlds. Gating =
12-producer, ρ > 0.28, class not collapse (9: 12-0050 0089 0092 0109 0330 0350 0384 0464 0494).
Reported: 42-producer loaded (3: 42-0066 0072 0102), light (12-0049 0211 0356), collapse
(12-0312), ρ quartiles (nearest rank within size). Any non-validation world is refused, dry runs
included. Episode seeds: `episode_seeds(world, n, "m4-es-validate")`, n = `--episodes` (4 or 8 by
5.4), every world (cyclic shock-free worlds too: their per-order arms still differ by key).

**Arms.** Per candidate (each run's `candidate.json`): the candidate (choice-v1, agent history,
R = 2) and its shared-only ablation (`history_mode="shared_only"`, same θ, R = 2); A0 (choice-v1,
R = 2); RR, MWW (R = 2, gate replicate action seeds), TR, all logits-v1. Per-order arms share
DrawKey(world, episode, replicate), so candidate / ablation / A0 pair by replicate. Producer
`entity_planner` only; no EXP-0035 column (the user's decision 2026-10-30). A `NonFiniteChoice`
in validation is a contract failure (the candidate is unusable, the read invalid).

**Floors (D7).** Per comparison, two levels:
- per world: floor_w = max(atlas floor_w, own 3·SE_w). atlas floor_w = max(3·SE_w, 0.01·bar_w),
  SE_w = `atlas.standard_error(n_w, differing_w, {compared stochastic arms: R}, spreads of
  (size, choice))` from the atlas v2 `spreads` — D12's formula **at the read's counts**. Own term
  = 3·stdev/√count of the paired observations (episodes × replicates), only with ≥ 2 (n = 1 rule).
- world mean (F_val(ref), F_tr): max(atlas term, own term). Atlas term = max(3·√(Σ SE_w²)/W,
  0.01·mean bar_w). Own term = 3·√(Σ_w s²/n_w)/W, s² = pooled within-world variance of the paired
  observations over worlds with ≥ 2 (df = Σ(n_w − 1)); none when no world has 2.
- bar_w: validation = max of the read's RR / MWW / TR world means; monitor = the bar table's B_we.
- F_tr: center vs A0 on the 16 monitor world-episodes (each its own "world": 1 episode, R = 2,
  stratum (12, its choice)). g_tr is recomputed from `monitor.csv` and checked against the run's
  monitor summary (1e-6).
- improvement = center mean at the last generation − at 10 generations before (monitor.csv);
  missing → "still improving" (unreachable in real 40-generation runs).

**Readings.** `analyse()` is pure. Seed 0: D6 selection (highest gating world mean; A2 within
F_val(A2 vs A1) → A1), then `unresolved` → `kill` → `success` → `plateau` → `budget_limited` →
`other`. Success clauses: beats A0 / RR / MWW / TR beyond F_val(ref); lost-to-RR worlds
(RR_w − cand_w > floor_w) × 6 ≤ worlds; zero candidate deaths; run-down and starvation **row
shares** ≤ RR's (shares, since the candidate has R = 2 and RR R = 1). Seed 1 (`--seed-combine`):
the same table, selection not redone, (ii) from seed 0, (i) = seed 0's (i) ∧ the seed-1 run
stopped, `budget_limited` from the seed-1 run alone; D7's combination table.

**Labels.** Computed for every candidate, recorded with a reading by D7's table (none outside
success / plateau); at the final read a label on either seed's candidate is recorded.
- `not_via_deconcentration`: candidate − A0 of `trace_lead_concurrent_top_share_consumer`
  (rows with ≥ 1 concurrent group; paired by episode and replicate; gating world mean) is not
  below −3·SE (pooled own SE, as the floors').
- `history_inert`: |candidate − ablation| ≤ F_val(ablation).
- `herding`: per gating world, candidate `share_swing_consumer` mean − MWW's > 3·SE_w (the
  candidate's own row spread, rows with swing pairs); flagged on ≥ 1/3 of the gating worlds.

**Power rule (frozen rule, not outcome).** Pairs MWW − RR and TR − RR on the EXP-0052 confirm
rows of the 9 gating worlds; a stochastic arm's per-episode value is its replicate mean (R = 2);
s = pooled within-world SD (worlds with ≥ 2 episodes); MDE(n) = 3·s/√n/√9 as a share of the
mean atlas bar (reclassified `worlds.csv` `bar`). **Deciding = the max over the two pairs**:
success needs every comparison to clear, so the read is as weak as its noisiest pair; taking
the max also means the choice cannot follow whichever value is smaller. ≤ 2% at 4 → 4
episodes, else 8; > 3% at 8 → to the user. `--mode power` applies it; the test checks only that
MWW − RR reproduces 1.2's 1.88% (34.5 / 1831.4), not the decision.

**Normaliser pins (carry-forward 5.1 / 5.3; widened in review round 1).** The "fitting code
hash" = SHA-256 over, per package-relative file in sorted order, the file name, NUL, the source
lines of the listed top-level definitions, decorators included, in list order (`# name` +
lines), NUL. Listed (`ow.NORMALISER_CODE_DEFS`): the fit / apply (`per_order_scorer.py` CLIP,
feature tuples, LOG1P_*, SCALE_FLOORS, transform_phi / psi, input_transforms,
apply_scale_floors, FeatureNormaliser, RawRows; `order_es_worlds.py` rows_digest, load_fit_rows,
fit_normaliser, fit_rows_sha256) **and the code that builds and feeds the rows**:
PerOrderPolicy (its `decide` transforms the rows for both the fit sink and the normaliser),
shared_rows, history_rows, order_features, `orderer_scorer.py` _product_features /
_producer_row_features and their feature tuples, and `env/agent_history.py` (AgentHistory, its
fold / reset hooks, priors, attach). Not covered, stated in `fitting_code.not_covered`: the
domain / env state those builders read (`product_stream_view`, bid outcome kinds), recorded by
each run's package tree hash only. It lives in
`NORMALISER_PREREG["fitting_code"]` (so in the prereg's `normaliser` section and in every bar's
`normaliser.json`), and `readings.normaliser_pins.rule_sha256` = SHA-256 of the whole rule block
(the rule text pinned by hash, not only by `median-iqr-log1p-v2`). The ±5 clip, the IQR → SD →
1.0 zero-spread rule and the scale floor are in the same block (and repeated in
`normaliser_pins`). A real validate run refuses a bar whose block hashes otherwise, and a
candidate whose normaliser is not the bar's.

**Probe.** `probe.theta` (frozen) = each arm's registered initial θ (Δ = 0); the readings'
`probe_interpretation` notes A2's structurally lower cosine without moving thresholds.

## Driver (pod-ready, mirrors decoder_check / order_es)

- `--workers N` longest first (size² × 3 for torch arms × 1.5 for the shared-only ablation);
  BLAS / torch one thread per worker (routing_audit's executor).
- Inputs by path: `--runs` (comma list), `--bar-dir`, `--atlas`, `--orderer-ckpt`, `--prereg`
  (default the packaged frozen file), `--reuse-references`.
- `--source-commit` / `--verify-source-commit`.
- Resume-safe on the same `--out-dir` (gate `_prepare_resume`): every pin must match — atlas,
  bar hashes, orderer, prereg SHA, episodes, sample, spreads, candidates (θ, composite,
  normaliser, training pins), **decode pins** (`ordering_decode: choice-v1` merged from
  `decode_pins`, `decode_by_arm` per arm, `per_order` identities incl. history mode), source
  tree and commit, grid. A decode change is refused before any job (tested).
- Contract failures, missing rows, digest differences → `invalid`, readings withheld, exit 2.
- A real run refuses: a prereg file other than `PREREG_SHA256` or with differing sections; a run
  trained under another prereg; a non-train (dry) run; a run not at generation 40; another atlas /
  orderer; a dry-run bar; horizon ≠ 100; episodes ∉ {4, 8}; no 40-hex commit; filters; a gating
  count ≠ 9 / 3; a bar normaliser block ≠ the frozen one.
- `--seed-combine --reuse-references <val-seed0>`: the seed-0 read must be complete, valid, with
  the same pins (`REUSE_PINS`, including the package tree) and a success / plateau reading; its
  rows are copied into the new `episodes.csv` (all digests re-paired), only the seed-1 candidate
  and ablation are played, the seed-0 reading must recompute to the recorded one, and the passed
  seed-0 run's θ must be the recorded candidate's.
- Writes `spec.json`, `episodes.csv`, `validation.csv` (per world × arm; per candidate by size ×
  group and size × ρ quartile, each with d / floor vs A0, RR, MWW, TR, ablation),
  `concentration.csv` (top share, dispersion, share swing; candidates, ablations, A0, MWW, RR),
  `herding.csv`, `reading.json`, `contract_failures.csv`, `RESULT.md` skeleton.
- `--mode recompute --out-dir <read> --runs … --bar-dir … --orderer-ckpt …` rebuilds the reading
  (MATCH / MISMATCH, `recompute.json`, exit 0 / 2).
- Never writes `experiments/m4_heldout_ledger.json` (task 8.1's).

## Gotchas for 5.4 and later

- **Power:** run `--mode power` (seconds, local); record `rule.deciding_pair`, `share_4`,
  `share_8`, `episodes`, `to_user` and the prereg SHA-256 in sizing.md. Its output also holds
  TR − RR; 1.2's carry-forward says TR − RR ≈ 2.50% at 4 → the max rule would give 8 episodes, but
  that is 5.4's computation to make and record.
- **Job counts (7.3):** 16 worlds × n episodes × (A0 2 + 2 candidates × (2 + 2) + RR 1 + MWW 2 +
  TR 1 = 14) = 224·n jobs (896 at 4, 1,792 at 8). 7.5 plays only 16 × n × 4 (256 / 512). The 42
  shared-only ablation costs more (history mean over a product's agents; 4.3 carry-forward:
  time it at 42 before sizing).
- **Same package tree for 7.3 and 7.5:** the reuse check pins the source tree. gate-v3 edits
  package files (e.g. `eval/baselines.py`) in this checkout; if such a commit lands between 7.3
  and 7.5, the seed-1 read refuses the reuse — rerun val-seed0 on the new tree first.
- **The frozen file pins code:** any edit to `order_es.registered_sections()` inputs, to
  `readings_registration()`, or to a `NORMALISER_CODE_DEFS` definition changes the prereg and
  fails `test_frozen_prereg_file`. Re-freezing (`--mode freeze` on a removed file, then the new
  `PREREG_SHA256`) is only legitimate before the first ES data (EXP-0058's bar).
- **Run dirs:** validation reads `monitor.csv` for the last generation's center rows and A0's
  rows, and the latest checkpoint's monitor history (the center 10 generations back, if the run
  was resumed past it); a staged run dir without `monitor.csv` or its last checkpoint cannot be
  read.
- **Sizing (5.4):** a resumed run (7.1) now replays A0's 32 monitor jobs once in its own dir
  (≈ 1/10 of a generation's 300 jobs; add it to 7.1's stop).
