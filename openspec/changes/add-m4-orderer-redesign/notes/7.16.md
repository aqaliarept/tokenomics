# 7.16: the reservation lifetime follows the world's order TTL (code, 2026-11-05)

## Change
- **`domain/producing_agent.py`:** `ProducingAgent(..., reservation_ttl=RESERVATION_TTL)` stores
  it, and the wait check is `cycles_waited >= self.reservation_ttl`. `RESERVATION_TTL = 2` stays
  as the default.
- **`domain/system.py`:** every producer is built with `reservation_ttl=self.order_ttl`
  (`Configuration.ttl`), so the reservation and the order lifetimes stay aligned. An order
  accepted in its first played cycle and a reservation waiting for inputs both end in cycle
  t + TTL.
- No other file changed. `domain/` is still pure.

## Other fixed lifetimes / 2-cycle assumptions (grep: `RESERVATION_TTL`, `ORDER_TTL`, `ORDER_LIFETIME`, `cycles_waited`, "2-cycle", "lead time", "ttl")
- **The reservation / failure path:** none left. The system's parent-order-TTL path already
  follows `Order.ttl` (7.12).
- **Still fixed at 2, off this path (both noted in 7.12):**
  - `train/per_order_scorer.py:369` `ORDER_TTL - order.cycle_counter`: inside the normaliser
    fitting-code hash, used by learned per-order policies only;
  - `eval/ceiling_bound.py:442/448` LP window default `ORDER_TTL`: the atlas bounds.
- **Defaults only:** `env/spaces.py` `ORDER_LIFETIME = 3` is the EnvSpec default, replaced by
  `build_spec` from the world TTL (7.12). The `domain/order.py` `ttl=ORDER_TTL` parameter
  defaults are overridden by `System`.
- **No producer-side assumption:** `entity_planner` (`domain/producer_planner.py`,
  `eval/baselines.py`), the producer view and the telemetry have no lifetime constant.
