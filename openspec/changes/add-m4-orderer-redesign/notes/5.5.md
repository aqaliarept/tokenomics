# 5.5 — uTWF router (`utwf`) and `decoder_check --mode arm-compare`

Rework (2026-11-02, user decision "Paper-faithful only"): the exact-demand WF arm
(`mww_waterfill`, which read the product's total ordered quantity from every agent's orders) is
removed from code, tests and CLAUDE.md. The arm is now the paper's unsplittable Tidal Water
Filling (uTWF), from local information only.

## Design note

### Why (the herding literature)
Every ordering agent of a product decides from the same start-of-cycle snapshot and cannot see
the others' choices (ADR-0058). If they all deterministically pick the producer that looks best,
they all pick the same one (herding). EXP-0057 shows it: the concurrent top share is 0.99 under
TW and 0.98 under TR. Drawing in proportion to spare capacity (MWWk) spreads them (0.73).

Goren, Vargaftik and Moses, "Distributed Dispatching in the Parallel Server Model" (DISC 2020,
arXiv 2008.00793), solve this with *Tidal Water Filling*. Each dispatcher randomises so that the
dispatchers' expected work, taken together, levels the servers. The *unsplittable* variant
(uTWF, §4.2, Definition 2) sends all of a dispatcher's jobs of a round to one server. It uses
only the dispatcher's own arrivals a^(m), the number of dispatchers M and the queue lengths Q.
It assumes the other M − 1 dispatchers received as many jobs as it did (the paper's heuristic
a^(1) = … = a^(M)).

### The paper's formulas (verbatim, with their numbers)
- **Algorithm 1, `WaterLevel(Q, a)`**: pour a units into the container shaped by Q, shortest
  queues first. While a > 0:
  - MinSet = the queues at Min(Q);
  - if every queue is in MinSet, return Min(Q) + a/|Q|;
  - δ = NextMin − Min(Q);
  - if δ·|MinSet| < a, raise MinSet by δ and set a ← a − δ·|MinSet|;
  - else return Min(Q) + a/|MinSet|.

  Implemented line by line in `routing_diagnostics.paper_water_level`, exactly, with
  `Fraction`s.
- **Section 3 / Eq. (1)**: Q*_n = max{Q_n, WL} and g*_n = Q*_n − Q_n. In §4.2, WL =
  WaterLevel(Q, M·a^(m)): the total load, under the equal-arrivals heuristic.
- **Footnote 5**: U = {n | Q_n < WaterLevel(Q, (M − 1)·a^(m))}.
- **Definition 2, Eq. (29)** (the same expression as Eq. (28), the KKT solution of Eq. (18) /
  (20)):

  p_n = max{0, [g*_n − (a^(m) − Σ_{n′∉U} g*_{n′}) / |U|] / ((M − 1)·a^(m))}

  Implemented verbatim in `routing_diagnostics.utwf_probabilities`. It evaluates g*, U, the
  bracket and the max for every n, with no shortcut.

### Mapping to the economy
| paper | here |
|---|---|
| server n | an eligible producer of product p (decode order) |
| queue length Q_n | Q_n = max_k m_k − m_n, with m_n = `makeable_qty_now` from the shared producer rows (`spare_queues`): more spare = a shorter queue; the most spare producer has Q = 0 |
| dispatcher m | the ordering agent (product stream) |
| a^(m), its arrivals this round | the summed quantity of the agent's own orders of p this cycle (`incoming`) |
| M | M_p = the product's number of product streams, from the configuration (`System.stream_products`, built by `product_stream_agents(config)`), whether or not they order this cycle |
| round | cycle |
| "sends all its jobs to server n" | one keyed draw per (agent, product, cycle); every order of p the agent routes goes whole to the drawn producer |

- **The mapping is shift-proof.** Water filling depends only on queue differences. A common
  shift c moves WaterLevel by c and leaves g*, U and p unchanged, so Q_n = c − m_n gives the same
  p for any c. The shift max m only keeps Q ≥ 0, as in the paper.
- **Proved in tests.**
  - `test_spare_capacity_is_the_queue`: c = max m, max m + 7 and 0 (negative queues) give the
    same p; the most spare producer gets the most mass; a small load puts all of it there.
  - `test_utwf_on_a_fixture_draws_eq_29_from_local_inputs`: on the shocked fixture, at every
    decision, the weights uTWF draws from equal Eq. (29) on (own a, configuration M_p, the
    producers' `makeable_qty_now`). That is 20+ decisions, ≥ 5 with ≥ 2 producers of positive p,
    and some with M_p ≠ the number of agents ordering that cycle.
- **Spare as a queue.** As in the paper's queues, the container has no top. A load beyond every
  producer's spare levels the excess evenly over all producers (`test_utwf_edges`).

### Why a^(m) is the sum, with one draw
The paper's a^(m) is "the jobs dispatcher m received this round", and uTWF sends all of them to
one server. An ordering agent that holds several orders of p this cycle (a new order plus
re-bids) therefore sums them, and all of them go to the one drawn producer. Each order stays
whole either way.
- Per-order draws would treat each order as its own dispatcher. That changes the paper's a and
  its unsplittable rule.
- It matters a little: EXP-0057's MWWk rows have 1.09 consumer / 1.18–1.20 producer orders per
  active turn.
- In product-stream mode an agent serves one product, so this is one draw per agent per cycle.

### The draw
- `inverse_cdf(p, keyed_uniform(key, agent, cycle, k))`, where k is the agent's first slot holding
  p. This is 2.1's keyed draw with MWWk's key, so uTWF − MWWk is paired (MWWk draws at the same
  uniform for that slot).
- p is computed exactly and converted to float64 for the draw. A zero-p producer is never drawn.

### Σ p_n, M_p = 1, a^(m) = 0, all-zero spare
- **Σ p_n = 1 exactly; nothing is normalised.** The paper gets primal feasibility from Lemma 1
  ("p_n > 0 iff n ∈ U") and the KKT conditions (Eq. (20)). Here p is exact (`Fraction`), and
  `utwf_probabilities` raises if Σ p ≠ 1.
  - Why it holds: with x = WL(Q, M a) − WL(Q, (M − 1) a) = (a − Σ_{n∉U} g*)/|U| (the paper's
    proof of Lemma 1), p_n = b*_n / ((M − 1) a), where b*_n = max{0, WL(Q, (M − 1) a) − Q_n}.
    Since Σ b* = (M − 1) a, Σ p = 1.
  - Tested on 3,000 random cases: Σ p = 1, the support is U, p equals this closed form, and ties
    get equal p.
- **M_p = 1.** Eq. (29) divides by M − 1 = 0. The paper's statement for M = 1 is JSQ: split the
  probability among the shortest queues. We give equal p to the producers with the most
  `makeable_qty_now`.
- **a^(m) = 0.** It cannot reach the router, since `place_order` drops zero-quantity orders. The
  paper does not cover it; Eq. (29) would divide by 0. We use the limit (M − 1)a → 0, which is
  also JSQ.
- **All-zero (or all-equal) spare.** All queues are equal, so WL = Min + load/N, U is every
  producer, and p = 1/N comes from the formula itself. No fallback is needed, and it matches
  MWWk's uniform. One eligible producer gets p = 1.

### Local information only (ADR-0058)
- **Inputs.** uTWF reads:
  - the agent's own `incoming`;
  - the static `stream_products`;
  - the producer rows (`makeable_qty_now` reads capacities, reservations and inventory, which
    the ordering phase never changes; `place_sub_orders` only appends to `p.bids`).

  It reads no other agent's orders and no total demand.
- **Tests.**
  - `test_utwf_ignores_other_agents_orders`: adding a 50× order of the same product to every
    other agent of the product leaves the target's inputs, weights and action byte-identical.
    The same extra quantity on the target's own order changes its a^(m).
  - `test_adr0058_utwf_turn_weights_equal_start_of_ordering_weights` (as in 4.3, cycles 2–7):
    each agent's inputs, weights, uniforms and action are equal at its own turn and on the
    start-of-ordering snapshot.
  - `test_adr0058_utwf_earlier_agents_leave_inputs_and_suborders_unchanged`: 2.1's permutation
    variants.

### Known limitation
`makeable_qty_now` is per product. It ignores competition from other products for the same
capacity, as in MWW / MWWk, so uTWF − MWWk isolates the water filling.

## Paper-faithfulness: every deviation from the paper
1. **Queue → spare capacity.** The paper's Q_n is a queue length that grows with dispatched
   work; here Q_n = max m − m_n, built from `makeable_qty_now`.
   - Water filling is shift-invariant, so only the differences matter, and they are the
     negated spare differences.
   - A paper queue can absorb any amount; a producer can accept only up to its spare this
     cycle. When the assumed load exceeds every producer's spare, uTWF still levels the excess
     evenly, as it would over queues, although no producer can take it this cycle.
2. **Rounds = cycles; jobs = order units.** The paper's jobs are unit-size and identical. Here a
   "job" is one unit of an order's quantity, and the dispatcher's batch is its orders of the
   product this cycle.
   - Orders are kept whole: the batch goes to one producer.
   - A producer's auction accepts a sub-order only if its whole capacity bundle fits (atomic),
     so a "server" can reject a batch, which a paper queue never does. Rejections show up only
     in the next cycle's spare.
3. **Servers do not serve FIFO.** Producers clear bids by price, inputs and capacity type. A
   multi-capacity recipe makes `makeable_qty_now` a min over types, not a single queue.
4. **M_p = the configured stream count.** Many streams never order in a given cycle; for example
   a producer's investment streams order rarely. The paper's M counts dispatchers. With the
   equal-arrivals heuristic, every idle stream adds a phantom a^(m) to the assumed total load
   M·a^(m), so uTWF spreads more than the actual load needs. This is the paper's own estimator
   (§4.1: M·a^(m) estimates a). The user's rule fixes M_p as static: it is not counted from this
   cycle's orders.
5. **Heterogeneous a^(m).** The paper derives uTWF under a^(1) = … = a^(M) and calls it a
   heuristic. Our streams differ widely in order size: consumer orders against small
   replenishment orders.
6. **Several products per producer.** The paper's servers serve one job class. Here one
   producer's capacity serves several products, and each product's agents fill it
   independently (the known limitation above).
7. **Edge cases outside the derivation.** M = 1 uses the paper's JSQ remark; a = 0, which the
   paper does not cover, uses the same JSQ limit; Algorithm 1 at a = 0, which returns nothing in
   the paper, returns Min(Q). a = 1 needs no fallback: there uTWF equals the paper's splittable
   TWF (reviewer: 0 mismatches in 2,000 cases). All-zero (all-equal) spare gives 1/N from
   Eq. (29) itself, no fallback.
8. **Randomness.** The paper's dispatchers draw independently. Here the draw is the 2.1 keyed
   inverse CDF (SHA-256 of world, episode, replicate, agent, cycle, slot), which pairs uTWF with
   MWWk. The draws remain independent across agents.
9. **Overflow orders** (beyond `k_stream`) count in a^(m), since they are jobs received, but they
   have no slot and decode even-splits them. This is moot on the sample: `trace_overflow_orders`
   is 0 on every EXP-0057 MWWk and RR row.

## `decoder_check --mode arm-compare --arm utwf`
- **What it runs.** The driver is unchanged except for names: `--arm` takes `utwf` only, the arm
  label is `uTWF`, the subject is `entity_planner/utwf`, the readings are `utwf_strongest` /
  `utwf_not_better`, and the compare columns are `utwf_rr_*`, `utwf_mwwk_*`, `utwf_ts_*`.
  - Jobs: uTWF (R = 2) and RR (R = 1) on every EXP-0057 world-episode, through
    `run_decoder_job` (EXP-0057's worker, `set_draw_key` per job): 213 jobs, longest-first.
  - RR / MWWk / TS are read from EXP-0057's `episodes.csv` (by subject), never rerun.
- **Checks** (exit 2):
  - contract failures and missing rows;
  - digests across this run's arms (`execute`);
  - every row's demand and shock digests against every EXP-0057 row of its world-episode
    (`reference_digest_problems`);
  - the RR replay against EXP-0057's RR row on every gate / scalar trace cell
    (`split_need.neutrality`, check `exp0057_neutrality`).

  A reference lacking a compared row is refused before any job.
- **Real run.** It needs:
  - the registered atlas (`220886a7…`);
  - the orderer SHA-256 `d25388bf…`, pinned only, since no arm plays it: it is the provenance of
    EXP-0057's TS rows;
  - EXP-0057 `episodes.csv` `69656f9e…`;
  - a frozen roster, horizon 100, a 40-hex commit and no filters.

  `--dry-run` allows `--worlds --max-worlds --horizon --shock-profile shocks-i-smoke`.
- **The pre-registered reading** (unchanged, WF → uTWF; `compare_reading`):
  - floor_w = max(atlas `noise_floor`, own 3·SE), with the own SE only for ≥ 2 paired
    observations;
  - `utwf_strongest` iff mean_w(uTWF − RR) > mean_w(floor_w), and mean_w(uTWF − MWWk) > its
    mean floor, over the 23 worlds at 12 producers, AND RR_w − uTWF_w > floor_w on at most 3
    worlds (6·n ≤ 23);
  - otherwise `utwf_not_better`; 42 producers are reported with the same rules; TS is reported
    only;
  - an alternative pooled-SE floor is reported only, never deciding.
- **Open point carried from round 1.** "Exceeds the floor on the 23-world loaded mean" is read as
  mean difference > mean floor. The supervisor has not objected; still flagged for the reviewer.
