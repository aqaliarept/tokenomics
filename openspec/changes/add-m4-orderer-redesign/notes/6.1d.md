# 6.1d: pre-registration v2 (minibatch 24 + disqualification noise margin)

Base HEAD 6f0eda6, not committed. User decisions "Bigger batches + fix rule" (2026-11-02) and
"Add a larger-sigma arm" (2026-11-03), both in notes/user-decisions.md.

**The cause addressed** is EXP-0058's `no_signal`, which EXP-0068 read as heterogeneous by the
registered statistic, on the 4-df reference. That reading is not robust: against the 24-df
per-world reference the same rule reads inconclusive, so flat at σ is not excluded. Separately,
the relative rule fires on draw noise (DIAGNOSTICS 25). v2's `changes.why` now carries the same
qualifier.

The supervisor settled the three questions this note first stopped on (2026-11-02). The stop
analysis is kept at the end.

## Decisions (supervisor, 2026-11-02)

1. **Margin.**
   - c = 2 on √2 × the pooled within-world SD across re-keys.
   - Run-down is pooled over all 12 EXP-0068 world-episodes, starvation over all consumers.
     Death is unchanged.
   - One number per flag kind. It applies only in D6's training-time rule (ES members and the
     probe), never in D7's validation clauses.
   - Registered as constants in prereg v2, with source rows and SHA.
2. **Target.**
   - ≤ 5% self-flags (≤ 2 of 48) on EXP-0068's rows.
   - A leave-one-world-out refit is reported only, never deciding. The circularity is stated
     plainly: the margin is fitted on the same rows, so the in-sample target is met by
     construction.
   - Not tuned to any probe or member outcome.
3. **Budget, option (a).**
   - Tranche A is extended to 125 vCPU-h, drawn only if EXP-0069 reads `signal` / `weak`.
   - EXP-0060b / d may carry stops up to 55 (2 × the estimate), a recorded exception to the 40
     cap.
   - The launch-fit is re-checked per run on billed spend against 125.
   - The ES design is unchanged (generations, pairs).
4. **Code note.** The size-24 probe minibatches come from the recorded stream, not from the bar's
   size-6 schedule. This is tested.

## Larger-step probe arm A1-S2 (2026-11-03; user decision "Add a larger-sigma arm")

- **Code: a per-arm σ fits cleanly, so nothing had to be built around it.** σ enters the probe
  in only two places: the member θ (θ ± σ·ε_i) and the estimate's scaling. The policy, θ layout
  and job path take θ from the job.
  - So A1-S2 is a label in `order_es.SIGMA_ARMS = {"A1-S2": ("A1", 2.0)}`.
  - `base_arm` / `arm_spec` / `arm_sigma` resolve it. `probe_noise` uses the base arm's
    stream, so the ε_i are the same. `run_es_job` plays `arm_spec(job["arm"])`, which is
    unchanged for every existing arm.
  - `per_order_scorer.ARMS` (frozen with PerOrderPolicy) and `TRAINABLE_ARMS` are not touched,
    so A1-S2 cannot train. The v1 `arms` / `probe` sections are byte-identical.
- **What is registered:**
  - v2 `probe.arms` = A1, A2, A1-S2, so a v2 real probe without A1-S2 is refused;
  - `probe.sigma_arms`: base A1, scale 2, σ' = 0.10, what is shared with A1, "diagnostic only",
    and the user decision;
  - the reading: D7's thresholds, a cosine ≥ 0.1 counting as `signal` / `weak`.

  | A1 (σ) | A1-S2 (2σ) | `step_reading` | next |
  |---|---|---|---|
  | < 0.1 | ≥ 0.1 | `flat_at_sigma` | the step becomes a design question; back to the user |
  | ≥ 0.1 | ≥ 0.1 | `heterogeneity` | minibatch 24 suffices; pilot at σ |
  | < 0.1 | < 0.1 | `no_signal` | DIAGNOSTICS entry; back to the user |
  | ≥ 0.1 | < 0.1 | `sigma_only` | reported; proceed with σ |

- **Licence.** `probe_reading` adds `a1s2_cosine` / `step_reading` / `step_next` only when A1-S2
  is played. Training is licensed by A1's reading alone, as registered.
- **One more fix.** A v2 probe's spec / probe.json `pre_registered` now carries the v2 probe
  section (it carried v1's). v1 is unchanged.
