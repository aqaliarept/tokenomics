## Definitions chosen (all recorded in `reading.json` `rules`)
- **Per-world means**: equal-weight over episodes of the replicate means (atlas D12, as in 1.2).
- **Atlas floor "at the run's counts"**: the atlas v2 entry's recorded `noise_floor`. The real
  run uses the confirm's episode counts, so these are the run's counts. This is 1.2's reading.
- **Pairing** (`paired_diffs`): per episode. When both arms have the same replicates, pair by
  replicate (TS − MWWk share keys, so up to 4 pairs). Otherwise pair every replicate of the
  stochastic arm against the deterministic arm's single row (TS − TW). RR − TR = episodes.
  "≥ 2 paired observations" counts these pairs. So a one-episode world has 1 RR−TR pair (atlas
  floor alone) but 2 TS−MWWk pairs (own 3·SE used).
- **Gap**: `G_w > floor_w` strictly. rec_w is computed for every world; only gap worlds enter.
- **Shares** (2/3, 1/3) are compared exactly in integers (`n·3 ≥ k·total`). rec_w uses float
  `≥ 2/3` / `≥ 1/3`, as in 1.2.
- **Fidelity**: `equivalent` if |TS_w − MWWk_w| ≤ floor_w, else `below` / `above`.
- **Dispersion**:
  - Per world: the value is averaged as for units, over TS rows whose count column > 0.
  - A world where a measure has no such row is undefined for it and skipped from the
    denominator (`skipped_worlds`, with the reason in `reading.json`). With no defined world the
    reading is `history_flat`, the conservative branch (the user is asked).
  - `borderline: true` when a pre-registered value on a deciding world (a 12-producer world in
    the reading) is within ±0.02 of its line. `borderline_worlds` lists them.
  - `borderline_changes_reading` reports whether forcing every in-band value to pass vs to fail
    changes the reading.
  - Alternatives (`producer_streams` with its own pair count; `vs_rest` and `unit_weighted`
    defined by `trace_routed_share_pairs`) replace the share measure in
    `alternatives_reported_only`, and `dispersion.csv` carries them per world and arm.
- **Score fidelity** (`reading.json` `score_fidelity`, `fidelity.csv`): per arm (TR / TS / TW),
  the median over episode rows of the per-row medians (Spearman vs log makeable, KL) and the
  decision-weighted top-1. Top-1 ties use the first argmax (2.1's wrapper). The **KL target**
  is named in `reading.json` `kl_target` and in the RESULT skeleton: softmax(`makeable_logits`),
  log m clipped ±10, a −10 logit for m = 0, uniform if nothing is makeable.
- **Secondary reads**: TS − TW mean and the count beyond its floor per size × choice cell and
  per ρ quartile. The quartile is nearest-rank (`atlas.quartile_cuts`) within each size. These
  rows also give the gap-world median rec_w per group. They are never gating.
- **Reproduction**:
  - EXP-0052: every TR / RR / MWW row of the run must have an equal row (units, `dead`, demand +
    shock digests) in EXP-0052.
  - EXP-0056: every TR / TW / RR row of EXP-0056 on a world-episode this run played must be in
    this run and equal. That means the first episode of 12-0060 / 0111 / 0344.

## Gotchas for 2.3 (timing probe) and 3.1 (pod run)
- **Cost estimate** (from 1.3 / 2.1 timings, not measured here at horizon 100 apart from the
  test):
  - a 12-producer episode is ~8 s for a scorer arm (TR / TS / TW) and ~2–4 s for a rule arm;
  - 42-0031 TR took 56 s;
  - per world-episode: ~45 s at 12 producers and ~6 min at 42;
  - total: 43 × 45 s + 28 × 6 min ≈ 3.3 vCPU-h serial. On 16 workers that is ≈ 13–15 min of
    wall time, bounded below by the slowest 42-producer scorer jobs (≈ 1 min each, so
    longest-first matters).
  - 2.3 should time one 42-producer TS and TW job and one 12-producer MWWk job, the arms 1.3
    never timed.
- **Memory**: every worker that runs a scorer arm imports torch (≈ 600 MB RSS), so 16 workers
  ≈ 10 GB. That fits 32 GB and does not fit this box.
- **The horizon-100 reproduction has been run here only on 12-0344's first episode** (the test).
  The first full check is the pod run. If `reproduction.csv` shows a mismatch, the run exits 2
  and the readings must not be used.
- **Resume**: rerunning the same command on the same pod `--out-dir` continues. A changed
  source tree (any `.py` in the package) is refused by the source pin, by design.
- **Exit 2 on reproduction** includes MWW r0 / r1 against EXP-0052. Those use
  `action_space.np_random` with `replicate_seed(world, episode, r)`, the same seeds as the
  confirm. Any change to `routing_diagnostics.ordering_makeable_weighted_whole` would show up
  here.
- **The 42-producer worlds are reported only**, but the run still pays for them: they are about
  80% of the compute. Dropping them would be a pre-registration change (D3), not a dry-run
  filter.
- **`reading.json` `dispersion.borderline`** is the literal supervisor rule, which is
  conservative. Read `borderline_changes_reading` beside it before calling the reading fragile.
