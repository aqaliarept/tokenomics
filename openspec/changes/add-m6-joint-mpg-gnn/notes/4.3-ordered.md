# 4.3: the order-aware accept pass (user decision 2026-11-07, after EXP-0123 `cost`)

**Problem (DIAGNOSTICS 38; EXP-0118 → EXP-0122).**
- The auction accepts a bid if it still fits after the items ranked above it: an ordered running sum against the
  free capacity.
- A set encoder (self-attention) learns it only approximately and misses the threshold: held-out accept 0.94–0.96,
  whatever the width, depth, epochs or input scale.
- In closed loop that costs units (EXP-0123: −56.7 per episode, via late pending claims).

## Choice: an additive recurrent pass over the turn's items in learned-priority order
`TurnHeads(ordered=True)`, after the set encoder:
1. The heads' own bounded priorities (bids and claims, from the attended embeddings) give each turn an order: descending,
   detached, ties in input order.
2. A recurrent pass visits the items in that order: h_k = MLP([e_k, s_{k−1}]), s_k = s_{k−1} + U h_k. The state starts
   at 0, and padded steps leave it unchanged.
3. A bid's accept logit is read from its h_k. The priorities themselves are unchanged (they are what orders the
   pass).

**Why the recurrent pass, not a causal attention mask by score.**
- A softmax-masked attention averages over the items above (its weights sum to 1), so it cannot represent a sum
  without also learning a count, and the threshold needs the sum.
- The additive state can hold the exact running sum: U h_k = the item's capacity when it takes capacity. It is
  also the simpler module: one MLP, one linear map, no extra attention.

**Gradient through the sort.**
- None flows through it: argsort is not differentiable, and the order is detached.
- The priority head learns from its pairwise ranking loss, as before (98.6% pair agreement in EXP-0120).
- The accept path learns given the order the student itself produces. Training and deployment use the same
  student order (teacher-forcing with the default order is not used), so the deployed path is the trained path
  (DIAGNOSTICS 37). Early in the fit the order is still poor; the accumulator then sees a moving order, which is
  what it will see at deploy.

**No hand-written rule.**
- No cumulative or "after pricier bids" feature is added. The inputs are v14's (log features; the linear fractions
  are not used, since they did not help in EXP-0122).
- The rank order comes from the learned priority. The accept bit, and what the state accumulates, are learned.

**Invariants (tests):**
- batched equals per-turn, in eval and train mode;
- shuffling a turn's items only permutes the outputs (no dependence on input order except through the learned
  order and its rare ties);
- with no set layers, changing the item ranked last moves no other item's accept logit;
- checkpoints round-trip;
- a tiny fit reaches full agreement.

The inputs are the producer's own turn features, unchanged (ADR-0062 §6).
