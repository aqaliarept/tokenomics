## The residual (design D2, made concrete)
- **θ:** 23 values = θ_k (9) + θ_b (9) + θ_e (5), shared by every producer and every input row.
- **Buffer per input:** k_g = 4 · exp(clip(θ_k · φ_g, ±2)), so k_g ∈ [0.54, 29.6].
- **Extra buying:** extra_g = round(max(0, θ_b · φ_g)) units on top of the planner's **want**
  (design D2). It is also bought when stock already exceeds the target (review m5-2-1 fix).
- **How both act.** Both raise the input row's demand pressure. The planner's target becomes
  max(3, pressure + blocked + ⌈k_g · use_g⌉) + extra_g, so neither the floor of 3 nor a stock surplus absorbs the extra (target = max(T, have) + extra_g, review m5-2-1).
  Headroom, the per-cycle ceiling and the fund gate bind as in the base. The input priority is
  scored from the unmodified view (as the base), through a new optional
  `plan_reservations_first(..., plan_view=)` in `eval/baselines.py`; None keeps every existing
  caller unchanged.
- **Expansion:** the base's triggers (headroom 0, or headroom below the blocked shortfall), plus
  θ_e · ψ > 0. It needs to be configured, not running, and affordable in the planner's spending
  order (restoration, replenishment, upgrade, expansion).
- **φ_g** (`INPUT_FEATURES`). The cover terms are each divided by 1 + use_g, where use_g =
  completed-units EMA × recipe:
  - bias;
  - stock cover, inbound cover, blocked cover;
  - log(1 + use_g);
  - headroom / limit;
  - EMA of past blocked shortfall / (1 + use_g);
  - max own completion latency of products using g, / 2 (TTL);
  - max product depth, / 3.
- **ψ** (`PRODUCER_FEATURES`): bias, headroom / limit, total blocked shortfall / (1 + total use),
  its EMA / (1 + total use), inventory units / limit.
- **Information set (ADR-0058):** the producer's own `ProducerEntityView`, plus an agent-local EMA
  (α 0.3) of its own past cycles' blocked shortfall per input. That EMA is weak-keyed by the system
  (M4 7.22's fix), restarts if the cycle counter goes back, and is read before the current cycle
  enters it. The fund level is read only for the base's existing affordability gate.

## Deviation from D2's feature list
D2 lists "the input's recent late count". The producer's view has no late field per input, so it is
replaced by an agent-local EMA of the input's past blocked shortfall (`shortfall_ema_cover`): units
its own reservations still lacked in past cycles. That is the observable precursor of a late or
expired input (review m5-2-1, note).
