# 4.2h: re-base on rf4 (2026-11-05)

**User decision:** "Adopt rf4 as base" (notes/user-decisions.md). The cap is treated as a safety fix, and
EXP-0084's `no_gain` stays recorded.

**Code:**
- **`producer_residual`:**
  - `RF3_PRODUCER` and `RF4_PRODUCER` constants; `BASE_PRODUCER = RF4_PRODUCER`.
  - `plan_residual(..., upgrade_cap)` drops the plan's upgrade when `over_sustainable_max(view)`, right after
    the base plan and before θ_e's expansion check. So θ = 0 with the cap is rf4, and without it rf3.
- **`producer_es`:**
  - Residual jobs carry `residual_base`, and `run_producer_job` sets the cap from it.
  - The bar's cross-check now replays the base against its reference rows: `--reference-episodes` (alias
    `--exp0079-episodes`), EXP-0084's rf4 rows for v5.
- **Pre-registration v5** = v4 with every rule's "rf3" read as rf4:
  - `_rebased`; provenance strings are kept;
  - `base` set to rf4;
  - the flag threshold, calibration and sources from `FLAG_*_V5`, which are None until EXP-0085's
    `--mode flag-calibrate`;
  - L1's pass text set for rf4 / EXP-0084.
- **Until v5 is calibrated and frozen,** `registered_prereg(5)` raises and `PREREG_SHA256` is None, so every
  real probe / train run is refused. Dry runs use v4's T, and pin it.
- v1..v4 rebuild byte-equal: the base section is pinned to `RF3_PRODUCER`.
- **`producer_read`:** the base arm label is `rf4`, and its references are k4 and `entity_planner`.
